# 合格リング（ホームタブ中央）設計仕様 — react-native-skia

- 日付: 2026-07-12
- 対象: まいにちJLPT `app/`（Expo SDK54 / RN0.81 / TS）
- ステータス: 設計確定（実装計画待ち）

## 1. 目的
ホームタブ中央に、世界観（桜・和・幻想）に合う**多重「合格リング」**を作る。参考画像 `画像/アプリ画像/ホームタブ.png` の三重構造を、**react-native-skia** でGPU描画し、発光・金の質感・エネルギーの光を実機で表現する。データ駆動（5科目カバー率・総合正答・合格可能性%・合格の称号）。

## 2. スコープ
### 対象
- **中央の合格リング・コンポーネント**（Skia）本体と、その**データ配線**・**適度なアニメ**・**ホームタブ中央への配置**。
- react-native-skia の導入（Expo prebuild 経由）。
### 対象外（ユーザー準備 or 別タスク）
- ホームタブの**背景画像**（ユーザーが用意）。
- ホームタブのその他要素（上部バー・今日の目標ボード・ボトムナビ）。今回は**中央リングのみ**。
- 合格率/到達度の算出ロジック自体（既存 selector を利用。無ければ最小の導出を足す）。

## 3. 確定した設計判断（ユーザー承認済み 2026-07-12）
1. **ビジュアル＝統合案**（A発光＋B金の可読性＋C高級な中央）。承認済みHTML: `デザイン提案/合格リング統合案.html`。
2. **ライブラリ＝react-native-skia**。
3. **アニメ＝適度に動く**（読み込みで弧が伸びる／中央が呼吸する発光／金の装飾が微回転）。

## 4. ライブラリ導入と含意
- 追加: `@shopify/react-native-skia`（Expo対応・autolink・prebuildで組込）。
- **重要な含意: Expo Go では Skia が無いため描画できない**。トンネル(Expo Go)ではプレビュー不可。
  - 確認手段 = **dev-client ビルド**（`expo-dev-client` を入れて内部配布）または **TestFlight/AAB の実ビルド**。
  - 開発中の即時確認性は下がる。→ 実装後は**ビルドして実機で確認**する運用にする。
  - （代替として「Expo Goでも見えるSVGフォールバック」を二重実装する案は、保守コスト高のため今回は**採らない**。必要になれば別途。）

## 5. リング構造・ビジュアル（統合案）
中心 (200,200) 基準・外→内:
- **外リング（知の精進＝カバー率）** r≈172, 太さ≈14。5科目（語彙/文法/漢字/読解/聴解）の**等分セグメント**（各72°・gap≈9°）。各セグメントは薄いトラック＋**科目色の発光弧**（fill=カバー率%）。科目色: 語彙#e75f86 / 文法#9a86ef / 漢字#e8934e / 読解#46b6d6 / 聴解#57c78c。外側に科目ラベル。
- **中リング（試験の実力＝総合正答）** r≈128, 太さ≈11。トラック＋**エネルギーの光弧**（水色→紫の線形グラデ、fill=総合正答%）。
- **中央（心の準備＝合格の称号）** r≈90。**桜色の放射グラデ・ディスク**＋金の縁。中央に金の明朝で称号（例「合格」）。背後に**呼吸する発光**（ぼかし）。
- **金の装飾**: 外周にダッシュの金環＋内側に細い金環（微回転）。
- **見出し（上から積む）**: 「知の精進」/`N1 合格可能性 72%`、「試験の実力」/`総合 82%`、「心の準備」、中央「合格」。
- 発光・ぼかし= Skia の `Blur`/`Shadow`/`Gradient`/`Paint` で表現（HTMLのfeGaussianBlur近似を実機品質で）。

## 6. データ契約と配線
リング本体は**データ非依存の純コンポーネント**にする:
```
type PassRingData = {
  passPct: number;            // 合格可能性% (0-100)
  level: 'N5'|'N4'|'N3'|...;  // 表示用
  overallAccuracyPct: number; // 総合正答% (0-100)
  tier: string;               // 中央の称号(例「合格」)
  categories: { key:string; label:string; color:string; coveragePct:number }[]; // 5件
};
```
ホーム画面側で既存 selector から算出して渡す:
- カバー率: `coverageBars`（語彙/漢字/文法）＋ 読解/聴解は該当アイテムの学習割合から導出（`idsRingPct` 類似）。
- 総合正答: `ringsFor` の平均、または既存の総合指標。
- 合格可能性 %・称号: 既存の到達度/合格率 selector（`badgeTierIndex` 系）。無ければ「カバー率×正答」の暫定式を1つ定義（プレースホルダでなく実装する）。
- 値が未取得のカテゴリは 0% 表示（欠損でクラッシュしない・nullガード）。

## 7. アニメーション（適度）
- **描画時**: 各弧を 0→値 へ 1.2s で伸ばす（Skia `useValue`/`useTiming` or Reanimated 連携）。全体を scale .92→1・opacity 0→1。
- **常時**: 中央発光の呼吸（3–4s ループ）、金装飾の微回転（60s/周）。
- `prefers-reduced-motion` 相当（端末の低電力/簡易設定）では常時アニメを止める配慮（可能なら）。過負荷にしない。

## 8. 配置
- ホームタブ画面の**中央**に絶対配置（ユーザー背景の上に重なる）。上部見出し・中央称号は背景に負けないよう発光/影で可読性を確保。
- リングは正方形・画面幅に対して ~92%。上下は背景の巫女/ボードと干渉しない中央やや上に置く（微調整可）。

## 9. 可読性・パフォーマンス
- 文字は金/白＋影で背景（明暗いずれ）でも読める。
- Skia キャンバスは1枚・再描画は値変化時のみ。常時アニメは軽量（blur半径を過大にしない）。
- 追加バンドル: skia のネイティブ分（数MB）。主役グラフィックとして許容。

## 10. テスト
- `npm run tsc` 緑。`npm test` 既存維持。
- **純関数のテスト追加**: データ導出（カバー率/正答/合格率→PassRingData への写像、カテゴリ欠損時の 0 埋め）を純関数に切り出し `*.test.ts`（package.json の test に追記）。
- 描画は**実機（dev-client/実ビルド）目視**で確認（Expo Go不可を明記）。

## 11. リスク・未確定
- **Expo Go 不可**（§4）: 確認はビルド必須。運用に織り込む。
- 合格可能性%/称号の正データ源が曖昧な場合、暫定式を1つ定義して実装（後で差し替え可能に isolate）。
- 配置の上下位置・サイズは実機で微調整前提。
