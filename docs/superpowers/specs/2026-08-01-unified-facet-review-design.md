# 面別マスタリー統合復習 設計書（2026-08-01）

## 1. 目的
学習の苦手度が複数の場所にバラバラに記録され、タブ・ボタンの役割が重複している問題を解消する。
**単語・字ごとの「面別マスタリー」に一本化**し、忘却曲線で駆動する**統合復習「試験問題の復習」**を中核に据える。
狙いは (a) UI の分かりやすさ、(b) 試験に備えた学習効率の最大化。

## 2. 現状の問題（背景）
同じ単語の「苦手度」が最大4つの別キーに分裂している：
- `項目#大問`（試験タブの各大問）
- `id#produce` / `#gbuild` / `#gmeaning`（書斎タブのドリル）
- 素id（聞き取りの記録＋私の単語帳の復習）
- `state.kakitori[字]`（書き取り・別スライス）

そのため「聞き取りで落とした語」「試験で間違えた問題」「書き取りで詰まった字」が互いに合流せず、
忘却曲線の効き方も倉庫ごとにバラバラ（試験＝期日あり／産出＝p順のみ／聞き取り＝無し／書き取り＝独自）。

## 3. データモデル：単語×面マスタリー
### 3.1 面（facet）＝試験の認識スキル
各項目に、適用可能な面だけを持たせる：
- `read` 読み（漢字読み）… 語彙(漢字含む語)・漢字
- `write` 表記（かな→漢字）… 語彙(漢字含む語)・漢字。※書き取り(産出)はこの面を底上げ
- `mean` 意味/用法（文脈規定・言い換え類義・用法）… 語彙のみ
- `listen` 聞く（語レベルの聞き取り）… 語彙・漢字
- `grammar` 文法運用（文法形式・組み立て・文章の文法・意味/用法をまとめて）… 文法のみ（文法の意味はこの面に含める）

### 3.2 保存
- 新スライス `mastery[itemId][facet] = ItemState`（既存 engine の ItemState/effectiveP を面単位で使う）。
- 各面が「保持率＋次回期日 dueAt＋reps」を持ち、忘却曲線を面ごとに適用。

### 3.3 補強（書き取り・産出）の扱い
- 独立の面を作らない。**合格するとその項目の対応面の保持率を底上げ**：
  - 書き取り(漢字) → `write`（副次的に `read`）
  - 産出タイル(語彙 意味→単語) → `mean`（副次的に `read`）
  - 文法作成(例文の空所に文法語) → `grammar`
- 試験に無いため**予想得点には直接加点しない**（面が上がって間接反映）。
- 産出は試験より難度が高いので、**失敗時は認識面を大きく下げない**（減点は軽め）。

## 4. 復習エンジン「試験問題の復習」
### 4.1 出題対象（membership）
- **既に一度でも触れた** (item, facet) のうち、**苦手（保持率が低い／間違えた履歴）**のものだけ。
- **新出（未習）は出さない**（新しい語は書斎タブの新出学習・試験タブの大問別練習で増やす）。

### 4.2 いつ出すか（timing）
- **忘却曲線**：`dueAt <= now` の面を、保持率(effectiveP)の低い順に。

### 4.3 出題形式（面駆動で活動を自動選択）
選ばれた (item, facet) の面に応じて出題を生成：
- `read` → 読み問題（既存バンク kanji_read / makeQuestion reading）
- `write` → 表記問題（orthography）。漢字は書き取りで出すことも
- `mean` → 意味・言い換え類義・用法（バンク）。深掘りに産出タイル
- `listen` → 聞き取り（ListeningQuiz 形式）
- `grammar` → 文法問題（バンク：形式・組み立て・文章）
活動は交互に混ぜる。学習後は既存の統一テンプレ（貝・単語帳チェック）を流用。

### 4.4 入口（同一エンジンへ複数入口）
- **ホームタブ**：AIコーチ（HomeCoach）のアドバイス横に「今日のおすすめ＝復習をはじめる」ボタン。
- **書斎タブ**：目立つ場所に復習ボタン（毎日のハブ）。
- 試験タブ：副次的に置いてよい（主役は模試＋大問別）。

## 5. タブ／ボタン構成
```
【ホーム】 AIコーチのアドバイス ＋ 復習ボタン（すぐ開始）
【書斎】   復習ボタン(目立つ) ＋ 新出学習 ＋ フォーカス練習(聞き取り/書き取り/産出=任意)
【試験】   模試 ＋ 大問別の個別練習（新出にも出会える）
【辞書】   私の単語帳の復習（面駆動）＋ 辞書
```
新しい語の入口は「書斎の新出学習」と「試験の大問別練習」の両方に残す。

## 6. 漢字書き取りの新フロー
- **学習ターン**：5字を「なぞり書き」で練習（お手本トレース）。
- **問題ターン**：お手本（なぞり字）を**見ずに**5字を書き取り採点。
- 合格 → その字の `write`（副次的に `read`）面を底上げ。
- 書き取り自身のスケジュール（既存 kakitori SRS の間隔 1/3/7/16/35 日）は維持。面マスタリーへは合否を反映。

## 7. 予想得点との関係
- 面別マスタリー → 各大問の到達度 → 予想得点、と一貫させる。
- 書き取り・産出は補強なので予想得点に直接は足さない（面が上がり間接反映）。
- 既存の passRate/facets の配線を面別マスタリー参照に更新。

## 8. 撤去・リネーム
- 試験タブの「全部混ぜ」ミックス出題（StudyHome の今日のオススメ／`category:'all'` 学習）を**削除**。
- 書斎タブの旧「今日のオススメ（産出/文法作成/文法意味の mixed ドリル）」を統合復習へ**吸収**。
- ラベル「今日のオススメ」→「**試験問題の復習**」にリネーム。
- 読解・聴解（長文）の復習は**対象外**（従来通り各タブで個別に）。

## 9. 既存データの移行
初回起動時に一度だけ（ガードフラグ付き・冪等）、旧キーを面へ寄せる：
- `#kanji_read` / `#reading` → `read`
- `#orthography` → `write`
- `#context` / `#synonym` / `#usage` → `mean`
- `#form` / `#order` / `#passage_grammar`（文法系大問）→ `grammar`
- 聞き取りの素id → `listen`
- `#produce` → `mean`（副次 `read`）、`#gbuild` → `grammar`、`#gmeaning` → `grammar`（補強として控えめに反映）
- `state.kakitori[字]` → `write`（補強として反映。kakitori スライス自体は書き取りドリル用に存続）
- 対応が曖昧なものは初期化。

## 10. テスト方針
- 面マスタリー更新（正誤→保持率・dueAt）、補強の底上げ（書き/産出→対応面）
- 復習の候補選抜（既習の苦手のみ・未習は出ない・忘却曲線順）
- 面→出題形式の対応（read→読み、listen→聞き取り 等）
- 移行マッピング（旧キー→面）が冪等
- 書き取り新フロー（学習ターン/問題ターンの分離・合否反映）
- 予想得点が面マスタリーから再計算される

## 11. スコープ外（YAGNI）
- 読解・聴解（長文）の復習統合
- 新しいゲーミフィケーション要素
- 予想得点の算式そのものの変更（面への配線更新のみ）
- AIコーチのアドバイス文言の高度化（入口ボタンの設置に留める）

## 12. 未確定・実装計画で詰める点
- 面ごとの ItemState を engine とどう共有するか（既存 buildQueue/effectiveP の再利用範囲）
- 復習1回の出題数と、面駆動の活動配分（例：due が多い時の間引き）
- 移行の細部（補強系キーの反映重み）
