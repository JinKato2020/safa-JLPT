## 1. 背景 — なぜ作り直すか

### 1.1 形式が丸ごと間違っている（最重要）

公式N5の言い換えは **文レベル**（提示された文に対し、ほぼ同義の**文**を4つから選ぶ）＝**N4と同形式**。
指示文＝「＿＿の **ぶんと だいたい おなじ いみの ぶんが あります**。」

アプリのN5 93問は **語レベル**（下線語に近い**語**を選ぶ）＝**N3形式**。**93問すべてが誤った形式**。

| | 公式 | アプリ現行 | 判定 |
|---|---|---|---|
| N5 | 文レベル | **語レベル** | **不一致＝要修正** |
| N4 | 文レベル | 文レベル（185問・stemあり） | ✓ |
| N3 | 語レベル | 語レベル（1000問） | ✓ |

**実測（2026-07-17）**: `app/content/problems/moji_goi/synonym_N5.json` の `stem` 保有＝**0/93**。

### 1.2 誤答が荒唐無稽（測定になっていない）

実データ（現行N5）:

```
朝  → 午前   誤答 = 果物・電車・財布
家  → うち   誤答 = 料理・名前・趣味
入口 → 玄関  誤答 = 天気・名前・値段
```

分野が全く違うため**語の意味を知らなくても当てずっぽうで消せる**。スキル `daimon-question-build` §2 が
「**現行アプリの欠陥そのもの**」と名指しした型。[[unique-answer-question-design]] 違反。

良い実例も混在する（「いかが→どう／誤答 どこ・いつ・だれ」＝疑問詞で揃う、
「大切→大事／誤答 元気・静か・親切」＝全部な形容詞）。**混在＝品質が保証されていない**。

### 1.3 漢字読み・表記を後回しにしてよい根拠

両者は**出題形式そのものは公式どおり**で、誤答も「音の崩し型」として機能している。
公式の半分を占める型（①の同カテゴリ別語＝雨→ゆき/はれ/くもり）が欠けており**痩せている**が、
**壊れてはいない**。言い換えN5は形式が丸ごと違い、誤答も測定不能＝**こちらが先**。

### 2.3 天井そのものが形式の間違いに由来する

公式N5の**山場2型は語→語の類義ではない**ため、`vocabSynonyms.json` に**構造上1件も無い**。

```
くらい      ≒ あかるくない        対義語＋否定（文の変換）
AがBに貸した ≒ BがAに借りた        授受の視点転換（文の変換）
両親        ≒ 父と母              上位語の分解（語→句）
```

**素材の在庫（実測）**:
- 授受ペア: 貸す/借りる・あげる/もらう・教える/習う・売る/買う・出す/入れる → **5ペアすべてN5内に存在**
- 家族語: 父・母・両親・兄・姉・弟・妹・兄弟・家族 → **9語存在**
- 対義語＋否定: N5形容詞から生成（`vocab.json` に品詞タグ無し。`app/dict/ja-vocab.json` の `pos` を使う）

→ **文レベルに直すと在庫の天井が消える。** 93という数字は「間違った井戸を掘った」結果。

## 4. 設計

### 4.1 データ形式 — N4の実物に揃える

**N4の185問が文レベル化の完成形**（出荷済み・verified）。そこに揃える。

```json
{
  "id": "sy:n5-v-12",
  "sentence": "その 店は 朝から あいて います。",
  "underline": "朝",
  "word": "朝",
  "stem": "その 店(みせ)は 朝(あさ)から あいて います。",
  "answer": "その 店(みせ)は 午前(ごぜん)から あいて います。",
  "choices": ["…文…", "…文…", "…文…", "…文…", "…文…"],
  "pattern": "noun",
  "verified": true,
  "i18n": { "ja": { "explain": "…" }, "ne": { "explain": "…" } }
}
```

| フィールド | 規則 | 根拠 |
|---|---|---|
| `stem` | **追加**。これがクイズ本体。ルビは**半角カッコ** `朝(あさ)` | N4実測＝半角。`daimon.ts:209` が `if (sy.stem)` で自動分岐 |
| `answer`/`choices` | **すべて文**（語ではない）。ルビ半角カッコ | N4実測 |
| `sentence`/`underline`/`word` | **絶対に消さない** | `daimon.ts:271` の**学習カード**が `sentence`/`underline` を読む。消すとカードが壊れる（[[verify-app-reads-the-file-you-edit]]） |
| 分かち書き | **N5は分かち書きあり**（N4は無し） | 公式N5。現行N5データも分かち書き |
| ルビ | `stem`/`choices` は**インラインの半角カッコ**。`RubyText` が描画 | `daimon.ts:208` のコメント＋N4実測 |
| `SENTENCE_FURI` | `sentence` 用に**別途必要**（学習カード経路）。全角カッコ | `daimon.ts:272` `markFuri(SENTENCE_FURI[sy.id] ?? sy.sentence, …)`。現行 sy:n5- は**85/93件**（8件欠け） |
| `pattern` | **新設**。§4.2の5型のどれか＝`hypernym` / `adj` / `verb` / `negation_cross` / `perspective_cross` | クロス型（誤答3個固定）を**機械で判別**するため。無いと §6 のテストが書けず、5型の配分も検証できない。UIは読まない（表示に影響なし） |

> **`stem` と `SENTENCE_FURI` はカッコの全角/半角が違う。** 機械変換で流用せず、両方を生成物として扱う。
> ふりがなは **LLMが正本**（MeCabは18%誤る＝[[sentence-furigana-needs-llm]]）。

**UIコードは1行も変更しない。** `stem` の有無だけで `daimon.ts:209` が
「だいたい同じ意味の文はどれですか。」（`format:'usage'`）へ自動で切り替わる。

### 4.2 5つの型と誤答数

| `pattern` | 型 | 誤答 | 例 | 誤答の作り方 | 何を測るか |
|---|---|---:|---|---|---|
| `hypernym` | 上位語の分解 | **5** | 両親 → 父と母 | 同じ関係の別ペア（祖父母/兄弟/姉妹）＝全部が家族ペア | 内外の使い分けを含む語群 |
| `adj` | 形容詞の言い換え | **5** | やさしい → かんたん | 全部を評価の形容詞で揃え、**1つは正解の対義語**（near-miss） | 評価形容詞の意味の網 |
| `verb` | 動詞の言い換え | **5** | せんたくする → あらう | 同じ目的語（服）を取る別動詞（ぬぐ/わたす/きる） | 動詞の意味の網 |
| `noun` | 名詞の言い換え | **5** | 朝 → 午前 | 同じ意味フィールドの名詞で揃える（時間なら時間だけ） | 名詞の意味の網 |
| **`negation_cross`** | **反対語の否定** | **3固定** | くらい → あかるくない | {あかるい, しずか} × {肯定, 否定} の交差 | **対義語＋否定＝等価**の論理 |
| **`perspective_cross`** | **授受の視点転換** | **3固定** | AがBに貸した → BがAに借りた | {主語の向き} × {貸す/借りる} の交差 | **主語が入れ替わると動詞も入れ替わる**対応 |

> 公式の型は5つだが、実データは名詞の言い換え（朝→午前・入口→玄関）が多いため `noun` を分けた。
> `noun` は「形容詞/動詞の言い換え」と同じ非クロス型＝誤答5個。

#### ★`perspective_cross` は「2×2クロス」ではない（パイロットで判明・**設計の根本誤り**・2026-07-17）

**当初の設計は「誤答＝2×2の残り3セル」と書いていたが、授受動詞では 2×2 が成立しない。**

**貸借・売買・授受の動詞では、4セルが「2つの出来事」にしか対応しない。**
1つの出来事に対し「貸す視点」と「借りる視点」の**2つの言い方が必ず同義**だからである。

```
{主語の向き} × {貸す, 借りる} ＝ 4セルに見えるが…

  先生が学生に貸した  ┐ 本が 先生→学生 に動く   … stem
  学生が先生に借りた  ┘ ＝【同一の出来事】       … answer（だから正解になる）

  先生が学生に借りた  ┐ 本が 学生→先生 に動く
  学生が先生に貸した  ┘ ＝【同一の出来事】       … この2つは互いに同義＝誤答に両方置けない
```

**実害（パイロット3問すべてで発生）**
1. 「残り3セル」と書くと3個目に **stem 自身**が入る＝100%の第2の正解（生成役が発見）
2. 残り2セルを両方誤答にすると**互いに同義**＝受験者は「答えは1つ」の原則から論理だけで両方消せる。
   結果、正解と近接動詞の**実質2択に退化**し、**向きの理解を測れなくなる**（反証パスBが発見。パスAは見逃した）

**確定した作り方（ユーザー承認 2026-07-17）**

```
stem : 先生(せんせい)が 学生(がくせい)に 本(ほん)を 貸(か)しました。
正解 : 学生(がくせい)が 先生(せんせい)に 本(ほん)を 借(か)りました。
誤答 : 学生(がくせい)が 先生(せんせい)に 本(ほん)を 貸(か)しました。 ← 逆向きの出来事【1つだけ】
誤答 : 学生(がくせい)が 先生(せんせい)に 本(ほん)を 返(かえ)しました。 ← 近接動詞
誤答 : 先生(せんせい)が 学生(がくせい)に 本(ほん)を 見(み)せました。   ← 近接動詞
```

- **逆向きの出来事は2つの言い方があるが、必ず片方だけ使う**（両方使うと同義ペアになる）
- **誤答ちょうど3個は維持**。4個以上だと `build4Choices` が3個抽出し、**肝心の逆向き誤答が抜ける回**が出る
- `negation_cross` は**この欠陥が無い**（明るい↔明るくない、静か↔静かじゃない は対義であって同義ではない）。
  両パスとも一致して clean。**stem が交差の外にある**ため 3個そのまま取れる

#### ★誤答どうしが同義なのも失格（パイロットで判明・規定に追加）

**誤答2つが互いに同義だと、語の意味を知らなくても両方消せる。**
答えは1つしかない以上、等価な2択は「両方とも誤答」だと論理だけで確定するため。

失格例（パイロットで実際に落とした）: 誤答に **晩と夜**が両方／**ちょっとと少し**が両方／
**どれとどちら**が両方／**大学と学校**が両方。

→ 一意性テストは「各誤答 vs 正解」だけでなく **「誤答どうし」も総当たりで見る**。
反証役にも `pairIssue` として報告させる。

### 4.3 【最重要】クロス型が3個固定でなければならない理由

`app/src/data/daimon.ts:172`:

```ts
export function build4Choices(answer: string, pool: string[], rng: Rng) {
  const distractors = pool.filter((x) => x !== answer);
  const picked = distractors.length > 3 ? sample(distractors, 3, rng) : distractors;
  return shuffleChoices([answer, ...picked].slice(0, 4), 0, rng);
}
```

誤答プールが**4個以上あると出題ごとにランダムに3個だけ抜き出す**（毎回同じ誤答＝暗記防止）。
→ **プールに4個以上入れた瞬間、2×2クロスの4セルのうち1個が毎回ランダムに欠けてクロスが壊れる。**

したがって **クロス型（否定等価・視点転換）は誤答をちょうど3個**にする。非クロス型は5個（暗記されにくく有利）。
**コード変更は不要**（データ側で個数を分けるだけ）。

| 2. **入れると今朝直した事故を再発させる** | `SY_GATED_LEVELS=['N5']` は、まさに廃止された当の設定 |
| 3. **入れても無意味（no-op）** | 本波は**N5を100%作り直す**ので、完了後 N5 は全問 verified。ゲートは何も濾さない |

**`verified` は「どこまで作り直したか」の進捗メタとして引き続き付ける**（コミット `edb076f` の方針どおり）。

**唯一の修正＝誤ったコメント**（挙動は変えない）:

`app/src/data/index.ts:198` の
「未検証(旧=分野違いの易しすぎるダミー…)は出題しない(daimonUnitIdsで除外)」は
`142b258` 時代の記述で、`edb076f` のゲート廃止時に消し忘れたもの。**事実と異なるので直す。**

> **教訓**: コードのコメントは**嘘をつく**。挙動の根拠は `git log` と実データで取る
> （[[verify-app-reads-the-file-you-edit]]）。本設計は当初この誤ったコメントを信じて
> 「ゲート欠落＝重大バグ」と誤診し、今朝修正済みの事故を再発させる寸前だった。

### 4.6 品質基準（全問共通）

- **正解は一意**（[[unique-answer-question-design]]）。各誤答を文に代入し、同義が成り立つものは**第2の正解＝不可**
- ダミーは**すべてN5範囲内の実在語**。範囲外（感冒・乳酪・美味しい・凸）は**易しくしてしまう**ので禁止
- **荒唐無稽な分野違いダミー禁止**（当てずっぽうで消せる＝測定にならない）
- **個人名なし・役割ベース**（[[content-borderless-no-names]]）
- **自分が確定した正解の近縁語を誤答にしない**（最頻出の失敗）
- 誤答が足りなければ **5→4** に減らす（第2の正解を作るより減らす。**減らすのは正当な判断**）

### 5.0.1 誤答どうしが同義なのも失格（パイロットで判明・規定に追加）

**誤答2つが互いに同義だと、語の意味を知らなくても両方消せる。**
答えは1つしかない以上、等価な2択は「両方とも誤答」だと論理だけで確定するため。

失格例（パイロットで実際に検出）: 誤答に **昼と午後**が両方（朝→午前の鏡像）／**どことどちら**が両方
（どちら＝どこのていねい形）／**うるさいとにぎやか**が両方／**晩と夜**／**ちょっとと少し**。

→ 一意性テストは「各誤答 vs 正解」だけでなく **「誤答どうし」も総当たりで見る**。
反証役にも `pairIssue`（同義な誤答の添字ペア）として報告させる。

### 5.0.2 表層の手がかりを残さない（本走行で **153問中43問(28%)** に検出）

**正解だけが助詞・語形・字種・長さで浮くと、意味が分からなくても選べる。**
本走行の反証2パスで43問に検出。**3つの型に分かれ、対処が違う。**

#### ★engineの3個抽出が確率で効く（この計算が判定の核）

engineは誤答5個から**ランダムに3個**抽出して4択にする。

| 正解と同属性の誤答（5個中） | 抽出3個から全部抜ける確率 | 結果 |
|---:|---:|---|
| 0個 | **100%** | 毎回浮く |
| 1個 | **40%**（C(4,3)/C(5,3)） | 10回中4回浮く |
| 2個 | **10%** | 10回中1回浮く |
| **3個以上** | **0%** | **浮かない** |

→ **揃わない属性は「誤答5個中3個以上」に持たせる。**（誤答3個固定のクロスは全部出るので0個か3個か）

#### ★★ 誤答を【4個】にすると 0% になる（修理役の発見・2026-07-17）

**「5個中3個以上」は万能ではない。** 属性を3:2にすると、**今度は少数側(2個)が全部抜ける回(1/10)に、
正解が「少数側でない方」として浮く**＝浮きが裏返るだけ。

**誤答4個・属性2:2 なら、3個抽出で必ず1個しか抜けない ＝【両方の属性が必ず残る】＝ 0%。**

```
誤答5個・属性3:2 → 少数側2個が両方抜ける回が 1/10  … 浮く
誤答4個・属性2:2 → 1個しか抜けない＝必ず両方残る   … 0%
```

実例: 「零→ゼロ度」でカタカナ3個にすると、マイナス系2個が抜けた回に正解だけ「マイナスの付かない語」として浮いた。
誤答4個（カタカナ2＋漢数字2）にして解消。「使う→利用」も同理由で4個（地下鉄を目的語に取れるN5の漢語サ変が2語しかない）。

→ **属性が2種類しか作れない語では、誤答を5個でなく4個にする方が強い。「減らすと強くなる」場合がある。**

#### 3つの型と対処（ユーザー判断 2026-07-17）

| 型 | 件数 | 例 | 対処 |
|---|---:|---|---|
| **A. 語形割れ** | 9 | `negation_cross` で正解「広くないです」（**い**形容詞）に2軸目が「きれいじゃないです」（**な**形容詞）＝否定形が割れ、「〜くないです」が正解だけ | **直す**（2軸目を同じ活用型に差し替え） |
| **B. 字の共有** | 14 | **母→お母さん**・昼→昼間・服→洋服・道→道路・旅行→旅・女→女性・危ない→危険・所→場所 ＝正解だけが下線語の字を含む | **受け入れる**。語ペアそのものの構造で、誤答側に同じ字を混ぜると意味が変わり不可能。**公式もこの型のペアを使う**（危ない→危険は典型） |
| **C. 属性不足** | 20 | 正解「トイレ」がカタカナだがカタカナ誤答が1個だけ／正解「学習します」が漢語サ変だが漢語サ変の誤答が1個だけ | **直す**（同属性を3個以上に。語彙の制約で無理なら `cannotFix` 申告） |

**Bを受け入れる理由**: 反証役に「疑わしきは valid にして拾え」と強く指示したため厳しめに出た。
字の共有は**弱い手がかり**であり、公式N5もこの型のペアを採用している。**直せないものを無理に直すと語ペア自体を失う。**

- **パスB はバッチを切り直す**（固定シードでシャッフル）。**同じ問題が別の隣人と一緒に判定される**ため
  判定が相関しにくく、取りこぼしを拾いやすい。同一バッチの再実行では相関して意味が薄い
- **どれか1パスでも valid なら削除**する。損害が非対称だから
  （誤って消す＝軽微・下限で保護 ／ 第2の正解を見逃す＝**バグ出荷**）
- **選択肢は【番号(i)】で同定する**。ふりがな括弧を含むためテキスト照合は表記ゆれで空振りし、
  **削除したつもりが削除されない**（実績あり）

**削除後の下限（§4.2の個数規則を割ったとき）**

| 型 | 下限 | 割ったら |
|---|---|---|
| 非クロス（`noun`/`adj`/`verb`/`hypernym`） | 誤答3個 | 5→4→3 まで減らして確定（**減らすのは正当な判断**）。3未満なら**変更せず報告**し、個別対応 |
| クロス（`*_cross`） | **3個ちょうど** | 1個でも消えたら**クロスが壊れる**＝軸選びの失敗。**その問題を捨てて別の軸で作り直す**（減らして4択にはしない） |

### 5.1 エージェント設計（[[workflow-subagent-efficiency]] 厳守）

| 段 | バッチ | 体数 | モデル |
|---|---|---:|---|
| 生成 | 型ごと・**30問/体** | **7** | **Opus high**（誤答の質＝この作業の存在理由。[[quality-critical-gen-use-opus]]） |

| **計** | | **21体** | |

**修理エージェントは置かない。** 削除は `tools/apply_synonym_audit.py` 相当の**ローカル機械処理**（トークン0）。
追加生成しないので**再反証も不要**（新しい第2の正解が構造的に入らない）。

> **N4実績は185問で16体＝約12問/体と細かすぎた。** 本設計は**30問/体**に束ねて生成7体に抑える

- **1バッチ=1agentの細粒度分割禁止**。30問/体に束ねる
- `pipeline(BATCHES, gen, verify→repair)` でバッチごと独立に流す（バリア不要）

### 5.2 Workflow の実装作法（過去に事故った点）

| 事故 | 対策 |
|---|---|
| `args` が undefined → agent が空配列 | **スクリプトにデータ埋め込み**。先頭データを目視確認 |
| CRLF で実行拒否 | Python書き出しは `newline='\n'`＋`assert b'\r' not in f.read()`（**バイナリで読む**） |
| agent が null → `.map` でクラッシュ | `if (!gen \|\| !gen.items) return {items:[],results:[]}` ／ `.filter(Boolean)` |
| cp932 で print が落ちる | `sys.stdout.reconfigure(encoding='utf-8', errors='replace')` |

### 5.3 救済3層（必須）

1. `journal.jsonl` に agent 完了ごと自動追記（**20問＝約10%ごと**にディスク保存＝バックアップ規定を構造的に満たす）
