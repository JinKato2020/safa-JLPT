# 書斎ストーリー（世界観・物語レイヤー）設計 v6 — 2026-07-28

まいにちJLPT に、世界観に沿った「物語レイヤー」を被せる。**核＝ユーザーの"願い"を世界の中心に据え、格を与える**こと。

**大原則**：課金・紹介・上限・出題・ショップの**仕組み（ロジック）は変えない**。物語は既存機能に**見た目と文言の"衣"**を被せる。壊れない・審査に影響しない。

関連正本：[桜-口調シート.md](桜-口調シート.md)（全台詞の判断基準・翻訳者にも渡す）。

---

## 0. 哲学（ここがすべての土台）

- **ユーザーはアプリを開く前から主人公。** 理由なしにJLPTアプリを落とす人はいない。物語の仕事は新しい目的を与えることではなく、**既にある本物の目的を世界の中心に据えて格を与える**こと。
- **使命を託さない。** 桜がユーザーに使命を託す（✗）／ユーザーが願いを立て、桜がそれを預かる（✓）。**桜はユーザーの願いを叶える存在**。
- **没入は目標にしない（結果である）。** 1日5分のアプリに深い没入は要らない。狙うと演出が長くなりスキップされ3週間で邪魔になる。「やらされている」を「自分の旅」に変えるのは没入でなく次の3つ：
  - **選択** — 門を選ぶ／筆を選ぶ／何を帳に書き写すか／桜に何を贈るか。決めているのが自分なら主人公。
  - **痕跡** — 壁の色紙、賑わう書斎、巡った季節。証拠が残る旅だけが自分の旅になる。
  - **承認** — 見ていた誰かがいる。願いを覚えている／戻ったことに気づく／苦手な語をそっと書き足す。**一番安く一番効く**。

## 1. 物語の軸＝「願い」（最優先・最初に固定する）

**なぜ最初か**：軸が決まらないと桜の口調も各演出の文言も後から全部書き直しになる。軸は演出を意味づけるだけでなく**これから書く数百本の台詞の判断基準**。P6まで行ってから通すと衣を全部縫い直すことになる。

- 導入物語の直後・**級選択の前に、桜が一度だけ聞く**：「なぜ、日本語を学ぶの？」
- 選択肢5〜6個 ＋ 任意で自由記述1行。**スキップ可**。
  - 例：日本で働くため／家族のため／大切な人と話すため／日本に住むため／夢のため（＋自由記述）
- **いつでも書き換えられる**＝軸がユーザーと一緒に育つ。架空の使命には絶対できないこと。
- 桜は**節目で必ず願いに触れる**：
  - 久しぶりの復帰：「おかえり。あの願い、預かったままだよ」
  - 大試の前夜：「◯◯のために始めたんだよね。いってらっしゃい」
  - 不合格の報告：**願いにだけ触れて、慰めない**
  - 合格の日：「叶ったね」と言ってから、**軸の書き換えを勧める**（人の理由は変わるから。ここが一番効く）
- 表現：書斎の**掛け軸**にできるかも（ホームに小さく見える）。
- **データ＝enum一つ＋文字列一行＋日付一つ**。Riveアセット1点より安い。受験日登録・合格報告と一緒に P0 に入る。

## 3. 物語①：入場（初回起動）

門→出会い→筆→**願い**→級選択→**初回セッション**→ホーム。文言先行・挿絵後追い（門と桜は既存アセットのシルエットで先に出せる）。

- **級選択を物語の中に入れる**：ドロップダウンでなく**門が5つ並び扁額に N5〜N1**。桜「どの門をくぐる？」。選択ロジックは既存のまま、見た目だけ門に差し替え＝事務画面が1枚減る。
- **筆を"渡される"だけで終わらせず一度使わせる**：渡された直後に画面を一度なぞる／叩く。触れた手応えが記憶に残る。
- **出口をホームにしない（最重要）**：入場 → 願い → 級選択 → その場で**3問だけの「ためし書き」** → **桜貝を1枚拾う** → 「明日も待ってるね」 → ホーム。初回セッション完了が翌日戻るかを一番強く決める。**核のループ（稽古→貝→桜が喜ぶ）をホーム説明の前に体験させる**。
- **桜貝は残高0で始めない**：入場時に桜が1枚手渡す（比喩は説明より手渡しが早い）。

## 4. 物語②：到達・合格（設計上の最大の要）

本試験の合格発表（12月・7月）は**このアプリで最も感情が動く日**であり、**解約・離脱が最も起きる瞬間**。ここを物語で受け止められるかがリテンションの分岐点。3層に分ける。

- **(a) 模試の合格ライン突破（頻繁）**：大試の門をくぐって戻る。**級ごとの初回だけフル演出**、以降は軽く。
- **(b) 貝殻リングが満ちる（級につき一度）**：「輪が満ちた」。ご褒美に**買えない筆か衣装を1点**（「この日のために取っておいた」）。**ショップ商品と競合しないもの**。
- **(c) 本試験の合格報告（本命）**：ホームに常設の小さな「**報告する**」導線。発表期の前後だけ桜から「そろそろ結果が出る頃かな」。**自己申告**でよい（下記の理由で不正の旨味を作らない）。

**演出の要点＝「消える演出」と「残る証」を分ける**
- 消える：花吹雪・柴犬全員集合（数秒で消える）。
- 残る：桜が筆でしたためた**記念の色紙（級と日付入り）が書斎の壁に残り続ける**。壁が埋まることが長期継続そのもの。
- **必ず演出の最後に次の門**：「次はどの門をくぐる？」→級変更。このとき**手習い帳と貝殻は持ち越せると明示**（「ゼロからやり直し」と感じた瞬間に人は消える）。

**不合格の報告フローを必ず同時に作る**（作らないアプリが大半・不合格者こそ翌期の顧客）
- 安い慰めは要らない。「よく門をくぐったね」＋**前回から積み上げた数字**（通った日数・解いた問数・帳から旅立った語数）を静かに見せる。手習い帳はそのまま残る。灯は消えない。**押し付けがましくないトーンが最大の資産**。

**報酬設計の注意**：報告の見返りは**記念品と見た目だけ**。桜貝を大量付与しない（自己申告×通貨は嘘の報告に旨味を生み演出が安くなる）。

## 5. 高ROIの追加接点

- **受験日を1つ登録**（日付フィールド1つ・どのフェーズより安い）：「大試の日まであと◯日」／前夜に桜が**お守りを無料で手渡す**／当日朝「いってらっしゃい」。
- **久しぶりの復帰**：3日・7日・30日ぶりで文言を変える。**絶対に責めない**。柴犬が最初に気づいて駆け寄る／灯が少し暗く、戻ると明るくなる程度。罪悪感で戻す設計は長期を焼く。
- **季節と時間帯**：実日付連動の背景4枚（桜・新緑・紅葉・雪）＋朝昼夜の差分。1年通った人にしか見えない変化＝長期の報酬。深夜は「無理しないでね」と**止める側の声**（キャラへの信頼が上がる）。
- **週1回「覚えた語」まとめ**：地味な反復に手応え。

## 6. 演出の減衰（共通レイヤー・独立させる）

接点ごとに「2回目以降控えめ」を書くと判定が4箇所以上に散り、テストも4通り、オフ要望に全部回ることになる。**方針テーブルを定数として1ファイルに独立**させ、うるさい時は**表の数字だけ**触る（コードを読まずにチューニング）。

- 全演出コンポーネントが **`variant: 'full' | 'short'`** を受け取る同じ形（デザイン発注も「フル版と短縮版の2つだけ」）。
- **lastGreetDay を吸収**：出迎えは `perDay: 1` の特殊ケース。専用フィールドを持たず、`daily_greet` の lastAt を日付境界で比較。※現状の暫定 `lastGreetDay` は本レイヤー実装時に吸収・削除する。
- **見落としやすい6点**：
  1. **付与と演出を完全分離**。`intensity==='none'` でも桜貝は必ず加算。付与は演出の外で先に確定（同じ if で括ると「4回目以降 貝がもらえない」最悪バグ）。
  2. **`none` を真のゼロにしない**。アニメが消えても `+3🐚` が上部バーで一瞬光る程度は残す（減らすのは演出時間であって手応えではない）。
  3. **スキップは最強の信号**。2回スキップで full→short、4回で none。
  4. **`refreshAfterDays`**：空白期間があれば full に戻す（復帰体験の質を決める一行）。
  5. **OS の Reduce Motion を1箇所で拾う**（全演出が同じ関数を通る）。
  6. **開発・QAリセット**を最初から：「演出カウンタ全消去」「強制 full」。無いと §テスト観点を実機確認できない。

## 8. フェーズ順（P0を先頭に・OTA可を先に）

P1〜P4 は既に定着した人にしか効かない（2日目以降に開く人だけが見る）。数字が最も漏れるのは**インストール当日〜翌日**で、そこに効くのは入場と願い。しかも **Rive はネイティブ＝OTA不可・要再ビルド**。願い・受験日・報告・減衰・台詞は**コードと文言だけ＝OTAで出せる**。差は初速に効く。

### P0（新設・画像ゼロ・OTA可）— 基盤は単独で出さず、最初の「利用者」と一緒に出す
1. **演出の減衰レイヤー**（§6・基盤）
2. **桜の口調シート＋台詞テーブル**（§7・基盤）
3. **願いの軸** — 既存 [OnboardingScreen](../../../src/screens/OnboardingScreen.tsx) に選択カードを1枚足すだけ（入場物語の完成を待たない）
4. **受験日の登録**＋大試前夜・当日の一言
5. **合格／不合格の報告フロー**
6. **計測3点**：インストール日・初回セッション完了・翌日起動（以降のフェーズ順を実測で決める）

### P1〜（画像・Rive・改名）
- **P1** 学習後の小演出（Rive・要再ビルド・要見積り）
- **P2** 起動の出迎え（lastGreetDay は P0 減衰レイヤーに吸収済み）
- **P3** 合格リングの意匠更新（男女ともに好かれる案・要画像・要見積り）
- **P4** 入場物語（文言先行・挿絵後追い＝門と桜は既存シルエットで先行）
- **P5** タブ改名（済：en/ja/ne）＋ホーム屋外化
- **P6** 機能の衣（課金＝奥書斎／紹介＝灯を分ける／模試＝大試）

**注意**：基盤（減衰・口調）は単体で出荷価値ゼロ。独立フェーズにせず P0 に混ぜ、願い・受験日・報告を最初の利用者にして基盤の形が正しいか即検証する（使われないまま作った基盤はほぼ確実に間違った形）。

## 9. 安全・コスト・非対象

- **安全**：課金/紹介/上限/出題/ショップ購入の**ロジックは不変**。衣（文言・画面・演出）だけ。自己申告の合格報告は**通貨を大量付与しない**（不正の旨味を作らない）。
- **コスト**：P0 は画像ゼロ＝実費ゼロ・OTA。Rive/新規AI画像（P1・P3・P4背景・季節4枚）は**着手前に点数×単価を提示**（D1）。
- **非対象（YAGNI）**：深い没入・長いカットシーン・複雑分岐／課金ロジック変更／5つ目のタブ／「帳をマスター」ゲーム化／書庫への演出。

## 10. テスト観点

- 願い：enum+文字列+日付の保存・**いつでも書き換え可**・スキップ可。桜が節目（復帰/大試前夜/合格/不合格）で参照する分岐。
- 減衰レイヤー：純関数。`variant` 判定・スキップ2/4回・`refreshAfterDays`・ReduceMotion・**付与と演出の分離**（none でも貝は入る）。
- 合格/不合格：報告フロー・記念の色紙が壁に残る・次の門・**手習い帳と貝殻の持ち越し**。
- 口調：24字2文・禁止表現の混入なし・反復回避（直近ID除外）。
- 既存 pro/ladder テストが緑（衣を被せてもロジック不変）。
