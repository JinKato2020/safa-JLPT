# token_report.py — トークン消費の定点観測

## 目的
毎回 scratchpad に使い捨てスクリプトを書かずに、いつでも同じやり方でトークン消費を確認する。
データ源＝`~\.claude\projects\**\*.jsonl` の `message.usage`（読むだけ・書き込みなし）。

## 使い方

| コマンド | 何が出るか |
|---|---|
| `python tools\token_report.py` | 既定。直近24時間を1時間刻み |
| `python tools\token_report.py --days 7` | 直近7日を日別に |
| `python tools\token_report.py --hours 6` | 直近6時間を1時間刻み |
| `python tools\token_report.py --sessions` | セッション別 上位15（直近7日） |
| `python tools\token_report.py --now` | **今の文脈サイズだけ1行**（一番よく使う） |
| `... --out memory\token.md` | 画面に加えて Markdown ファイルにも書く |

`--now` の例：
`現在の文脈: 45,353 (5万) / 200,000 = 22.7%  [session c3bf75d1 / 往復 19 / 最終 07/19 14:42]`
→ 割合が 60% で「注意」、80% で「★圧縮間近」が付く。そこが /clear の目安。

## 出力の読み方

- **文脈** ＝ `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`。
  1往復で読み込まれた会話全体の大きさ。
- **MAIN** ＝ 対話本体。**裏方** ＝ workflow（`wf_` で始まるフォルダ）とサブエージェント。
  この比率で「本体が重いのか、裏方が重いのか」が分かる。
- **文脈読込が全体の 98〜99%** になるのが正常。出力は 1〜2% しかない。
  理由＝**往復ごとに会話全体をまるごと読み直す**ため。だから
  「会話を短く保つ」「往復回数を減らす」が効き、出力を削っても効かない（親 CLAUDE.md の A 規律）。
- **合計** ＝ 文脈読込＋出力。数字は3桁区切りで、1万以上は「◯◯万」、1億以上は「◯.◯◯億」を併記。

## 仕様メモ

- 画面出力は**必ず30行以内**（超える分は中間を省略）。全文が要る時は `--out` でファイルへ。
- 期間指定がある時は、ファイルの更新時刻で対象外を足切りするので速い（全体は約2.3GB）。
- `--sessions` の「最大文脈／平均文脈」は MAIN のみ、「合計」は MAIN＋裏方。
- 最大文脈が autoCompact(200,000) を超えて見えることがある＝1Mコンテキストのモデルで
  動いていたセッション。異常ではなく、そこまで会話が育っていたという意味。
- コンソールが cp932 でも落ちないよう UTF-8 で出力する。
