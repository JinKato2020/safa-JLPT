# 聴解スキル（統合版）— JLPT聴解 全区分の本番音声（確定 2026-07-02）

聴解1(発話/即時)・聴解2(課題/ポイント/概要 Pro)・聴解3(同 Flash)を**1本に統合**。**音声制作ルールを統一**し、**テキスト作成ルールだけは各区分固有で温存**する。正本Excel＝`問題\聴解.xlsx`、音声＝`問題\聴解\<lv>\<区分>\<ID>.mp3`、マスター＝`_master\<区分>\<ID>-枝番.wav`、ビルダー＝`問題\tools\build_choukai3.py`。

## 1. エンジン（確定）
- **Gemini 2.5 Flash TTS（`gemini-2.5-flash-preview-tts`）＝既定。** 全区分これで作る。
- **Chirp3は本文に使わない**（日本語イントネーションが不自然・2026-07-02ユーザー判断）。
- 番号クリップ(1〜4)だけは**合格済Chirp3クリップ**（`_numbers\Charon|Leda\1..4.wav`・原速）を使う。
- 表現を特に強めたい特例のみ Gemini 2.5 Pro TTS に切替可（通常は使わない）。

## 2. 声（確定）
- **男＝Charon／女＝Leda。ナレーター（導入・設問）＝Aoede。**
- **対話で同性が2人いる場合の2人目＝男2=Orus／女2=Kore**（2026-07-02 試聴で承認）。話者(役割)ごとに声を固定＝男1 Charon/男2 Orus・女1 Leda/女2 Kore。3人目以降は2人目声を再利用。
- 音声回答（選択肢）は**番号と同一話者**。発話/即時など単一話者区分は問題ごとに男女を散らす(50/50)。

## 3. 区分別の音声構成
- **課題理解／ポイント理解**：`導入(Aoede) → 本文 → 設問(Aoede)` で終了。**回答は読まない**（画面のイラスト/文字4択）。質問は導入・設問で**前後2回**。
- **概要理解**：`導入 → 本文 → 設問 → (番号+選択肢)×4`。**選択肢を音声で読む**。
- **発話表現**：`本文(状況+「何と言いますか」) → (番号+選択肢)×3`。
- **即時応答**：`本文(投げかけ1文) → (番号+選択肢)×3`。
- 対話/独話は公式で確認（本文に「男(役割)：/女(役割)：」2種→対話、無し→独話）。

## 4. 生成のしかた（統一・確定）
1. **ナレーション（導入・設問）はAoedeで一定に＝まとめて生成して声を揃える。**
2. **本文の対話は 男Charon／女Leda（同性2人目=男Orus／女Kore）。話者ごとに【全発話を1コールで生成(=同一音声)→波形の無音で分割→対話順に並べ直す】**（＝相手の割り込みで分断されても**同一話者は最後まで同じ声**）。旧「連続ブロックのみ1コール」は分断で声がブレるため廃止（2026-07-02）。Flashはマルチスピーカー不可。独話は1コール。ブロック間0.3s連結。
   - **★分割は「波形の無音を実測して長い順にN-1個」＝文境界（2026-07-02実測で確立）**。期待時刻や句読点分類は使わない（中間の読点を誤検出して対話が崩れる＝K-009スクランブルの原因）。実測: **文の間≈600〜760ms／文中の読点≈90ms未満で約7倍差**＝明確に分離可能。`split_by_silence(pcm,n)`＝silencedetectで内部無音を取り、長い順にn-1個の中点で切る。
   - **★自動検証ゲート（再発防止の要）**：生成した各問を**Flashで文字起こし→台本(導入+本文各行+設問)とLCS一致率で照合**。**0.80未満は崩れ→per-turn個別生成で自動再構築**（順序完全保証）。実績: 課題理解N5でK-004が0.67検知→再構築0.98。`verify_problem()`。
3. **各生成に【スタイル指示】を前置き**：「標準語の**自然で正確なアクセント・イントネーション**で、落ち着いた同じ口調で（対話は"暗い声にならないよう"を追加）」。指示文は読み上げられない（Flash検証済）。※声の“完全一致”はGemini仕様上保証不可。
   - **★入れてはいけない指示（アクセントと競合＝2026-07-02実証）**：「**一定の高さ**」（ピッチアクセントを潰し「わ」等が不自然）／「**語尾を上げて**」（疑問文が必ず上がらない）／「**一語一語はっきり丁寧に**」（区切り気味の慎重発話になり自然な抑揚を潰す）。**明瞭さ・語尾より"自然で正確なアクセント"を最優先**。
   - **★誤読とアクセントは別問題**：誤読（例 係→けい）は`漢字（かな）`ふりがな固定で確実に直る。**アクセント（音程）崩れはふりがな不可＝再生成で引き直す**（Flash仕様上、指示で確実制御は不可）。**ふりがなは誤読する語だけにピンポイント**で（正しく読める語に付けるとかな化で抑揚が崩れる＝九番の例）。
4. **選択肢を読む区分（発話/即時/概要）は【合格番号クリップ ↔ 音声回答】を交互に**：`番号1→回答1→番号2→回答2→…`。番号=原速(Chirp合格クリップ)、回答も原速(1.0)。
   - **★本文は単独で1コール＝完全朗読（分割しない）**。**選択肢だけを1コールで生成→無音分割**（本文の「。」に釣られて途中で割れるのを防ぐ／3択は同一声に揃う）。**分割後は各回答をトリム**して番号↔回答の休止を固定値どおりに（長すぎ防止）。選択肢コールには「1つずつ区切って・番号は言わない」指示を付ける。分割失敗時のみ個別生成にフォールバック。
   - 1問1声＝本文・選択肢は同じ話者(男Charon/女Leda・問題ごとに50/50)。**正解位置は等分布(例10問→4-3-3)にシャッフル**し、正解列に番号を記録(常に1にしない)。
5. 空応答対策：Flash生成が空/極端に短い時は数回リトライ→なお空なら**Chirp3-HD 同声名にフォールバック**（Chirpには指示を前置きしない＝読み上げるため）。

## 5. 速度・間・音量（確定）
- **速度**：本文・導入・設問・選択肢・番号すべて**一定1.0倍**（レベル非依存・resampleは廃止 2026-07-24 ユーザー決定）。
- **間**：`導入 →1.4s→ 本文 →1.6s→ 設問`。概要は続けて`設問 →1.0s→（番号 →0.3s→ 選択肢 →0.6s）×4`。発話/即時は`本文 →1.0s→（番号 →0.4s→ 選択肢 →0.8s）×3`。対話の話者ブロック間=0.3s。
- **音量**：全パーツ **-20dBFS RMS**（ピーク-1dB）。

## 6. テキスト作成ルール（統合しない・各区分固有）
- ボーダーレス（人名・固有名詞なし・役割ベース）、**漢数字**、**正解=選択肢1**、話者ラベル(男：等)は音声化前に除去（対話は話者割当に使用）。
- 発話表現=状況+「何と言いますか」+3択／即時応答=投げかけ1文+3応答。
- モーラは公式に合わせる。詳しい作問作法は `listening-question-build` を参照。

## 7. 保存・検証・記録・後始末
- 音声＝`問題\聴解\<lv>\<区分>\<ID>.mp3`、マスター（正規化原音）＝`_master\<区分>\<ID>-枝番.wav`。
- **各mp3をGemini Flashで文字起こし検証**（導入・本文・設問・番号+選択肢が漏れないか）。NGのみ再生成。
- **Excel「音声(モデル/声)」欄にモデル+声を記入**（恒久ルール。例：`Gemini 2.5 Flash TTS / 導入設問=Aoede・対話=Charon/Leda(行分割・安定化指示)`）。
- **実費を報告**（Flash・円換算）。1000円超は事前見積→承認。一時wav削除・master/mp3保持。

## 8. ビルダー・キー
- ビルダー＝`問題\tools\build_choukai3.py`（課題/ポイント/概要を実装。発話/即時も本統一方式に合わせて対応）。ID指定＝`ONLY=<ID,ID>`環境変数。
- Gemini APIキー＝`build_choukai_audio.py` の `GEM`（直書き・印字しない）。番号Chirp＝`多言語教材\00_共通\tools\gtts_google.py`。ffmpeg/ffprobe・SR24k mono。
- 旧スキル(listening-skill-1/2/3)は本統合版に置き換え。
