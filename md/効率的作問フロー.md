# 効率的作問フロー（LLM一括生成・機械ゲート方式）

作問の中心思想 ＝ **「作ってから直す」をやめ、「作る前に基準を全部渡し、作った直後に機械で門前払いする」**。
作り直し（リドゥ）はトークン・費用の二重取り。これをゼロに近づけるための定型。
**2026-07-22 に情報検索・各級10問＝計30問のパイロットで実測・検証済み**（結果は下段）。

## 適用と前提
- 対象＝LLM（Gemini/Claude）で大量作問する大問（情報検索・文脈規定・読解 等）。
- 実測前提（情報検索・2026-07-22時点）: 1問 ≈ **9KB**・**日本語のみ**（多言語i18nは持たない）。`answer` は図表の行/条件で一意に定まる。

## 過去の実害（なぜこの型が要るか）
- **6問リドゥ**: 初回生成が字数不足で全6問作り直し（変化量 810+/453−）＝実質2倍コスト。→ 受入基準を最初に渡していれば防げた。
- **N3が不成立**: Gemini が情報検索N3の一意性（2段階計算・締切逆算）を満たせず 0問生成→手書きに。**難度が上がる級ほど一発合格率が落ちる**。→ 級ごとに一発率が違う前提で、落ちた問題だけ作り直す設計にする。

## パイプライン（検証済み・8段）
0. **仕様確定（数値化）**: 字数下限・一意性・難度・図表形式・ボーダーレスを数値と規則で確定。
1. **プロンプトに受入基準を内蔵**: 上記を全部プロンプトに書き、作問者自身に自己検証（自分の答えが唯一かの点検）を書かせる（B3＝独立verifyは倍コストなので基本は自己検証）。
   - **字数は「構造量」で強制する**のが効く: 「◯字以上」だけだと5〜7割しか出ない。「表に◯行以上・注記◯個以上・本文◯文以上・情報源◯枚」と**構造の最低量**を指定すると届く（パイロットで字数達成 6/30 → **28/30**）。
2. **生成は束ねる**: 「1レベル1コールで複数問」まとめて出力（B2）。1問1コールに割らない。**この段でルビの完璧さは求めない**（下の第3段に分離）。
3. **ルビは独立の決定的工程（重要な発見）**: 生成と同時に全漢字ルビを完璧に付けさせるのは**モデルの性質に反し不可能**（円・日・時・料 等の常用漢字を「簡単だから」と素通りする。パイロット round2 で1問あたり20〜78字が無ルビ）。
   - 正解＝**モデルに本文を再出力させない**。①機械が「まだ（読み）が付いていない最長の漢字連」を検出 → ②その語（＋送り仮名の手掛かり文脈）だけをLLMに渡し**読みのみ**を取得 → ③機械が `漢字（よみ）` を該当箇所へ**決定的に挿入**（文字列外科手術）。
   - これで空白ズレ・構造破壊が**原理的に起きず**、ふりがなの正本はLLM（[[sentence-furigana-needs-llm]]）を守れる。パイロットで**無ルビ 全級0字・¥2**で達成。
   - ✕やってはいけない設計＝「JSON全体をモデルに再生成させて base 不変を検査」: N5の分かち書き（全角スペース）や大問の再現に失敗し**全問差し戻し**・N3は出力トークン超過で途中切れ（round1 で実際に全滅）。
4. **機械ゲート（LLM不要・¥0）**: 生成JSONを自作スクリプトで即判定し、**落ちた問題だけ**返す（下の「チェック項目」）。ここで形式・字数・ルビ0・ボーダーレスを無料で保証。**ゲートのルビ判定はアプリ `RubyText.tsx` と同一正規表現**にする（誤検出ゼロ・[[qa-name-ruby-false-positives]]）。
5. **一意性はLLM反証（安価・必須）**: 答えを隠し「全条件を満たす選択肢を全部挙げよ」を独立判定。ちょうど1つ＝合格／複数・ゼロ＝NG。**機械ゲートでは絶対に見えない欠陥**（正解が2つ）を捕まえる。パイロットで¥4/30問。**N3は特に必須**（下記歩留まり）。
6. **再生成は落ちたIDだけピンポイント**: 全リドゥ禁止。同型プロンプトで失敗IDのみ作り直し→再ゲート。**難級で連続失敗する問題は、より強いモデル（Opus等）へ昇格**して作らせる（[[quality-critical-gen-use-opus]]）。
7. **反映（決定的パイプライン一括）**: content置換 → `node --import tsx tools/content/rebuild.ts`（目録＋barrel再生成）→ `npx tsc --noEmit` → 契約テスト（`node --test`）→ コミット（**明示パスのみ**・`git add -A`禁止）。目録はCIの deploy-pages で公開直前に自動再生成される（[[ota-manifest-regen-or-stale]]）。

## 機械ゲートの具体チェック（すべて¥0・LLM不要）
- **字数**: ルビ除外の実字数 ≥ 下限（情報検索の目安 N5 250 / N4 400 / N3 600）。本文＋“地の文”（注記・説明文）で計測。表のラベル文字は字数に数えない。
- **構造**: 選択肢が4・正解が1・`answer` が実在する行/条件に対応。`figure` 必須欄（`kind`/`blocks`/`notes`）が揃い描画が落ちない形。
- **ルビ**: アプリ同一正規表現で**無ルビ漢字が0**。かな・数字・記号には付けない。
- **ボーダーレス**: 個人名・実在地名の禁止語にヒットしない（役割名・一般名のみ）。[[content-borderless-no-names]]。※パイロットで「田中」「マリア」等が漏れた → **禁止語は漢字名＋カタカナ人名も列挙**し、プロンプトも「登場人物は必ず役割名（留学生・利用者・会員・親子）で書く」と明示。
- **難度（スキャン負荷）**: 条件の **1つ以上が表ラベルでなく地の文（注記/説明）に埋まっている**こと。

## パイロット実測（2026-07-22・情報検索・各級10問＝計30問）
モデル＝Gemini `gemini-3-flash-preview`。
| 級 | 字数達成 | 無ルビ | 機械ゲート | **一意性(反証)** | 実質良品 |
|---|---|---|---|---|---|
| N5 | 10/10 | 0 | 9/10 | **10/10** | ~9/10（残1＝人名混入・即修正可） |
| N4 | 8/10 | 0 | 7/10 | **10/10** | ~7/10（残＝図表構造/字数境界・軽微） |
| N3 | 9/10 | 0 | 9/10 | **5/10** | **~5/10（一意性が律速）** |

- **要点**: N5/N4のダミー設計は出題者意図どおり成立（各誤答が別々の1条件で外れる）。**N3は締切逆算・合計金額・割引の2段階計算が第2の正解を生み、半数が一意性破綻**。これは機械ゲートを通り抜けるので**第5段の反証が必須**。
- **一発合格率（実質）**: N5≈90% / N4≈70% / N3≈50%。→ 目標数に対する生成オーバーヘッド: N5×1.15・N4×1.5・**N3×2＋反証落ちの再生成**。N3は歩留まり次第でOpus昇格。

## 不合格の直し方（8割自動採用・2割だけ理由別に最安修正）
思想＝**一発100%を狙わない**。まとめて生成し、機械ゲート（¥0）＋一意性反証（¥数円）で「採用」と「要修正」を自動仕分け。**採用（約8割）はもう触らない**。要修正（約2割）だけを**落ちた理由ごとに一番安い手段**で直す。全リドゥ（作り直し）は最終手段。

| 落ちた理由 | 最安の直し方 | コスト | 作り直し不要な理由 |
|---|---|---|---|
| 人名・実在地名の混入 | 機械で役割名/一般名に辞書置換。曖昧なら極小LLM | ほぼ¥0 | 本文・図表・設問は正しい |
| 字数が下限を少し下回る | その1問だけ「注記/行を増やして◯字以上に」と1コール | 数円 | 中身は正しい・量だけ足す |
| 図表の形ズレ（blocks欠け等） | 機械で正規の形へ整形 | ¥0 | データは揃っている |
| ルビ | 第3段の機械工程で常に0字（そもそも落ちない） | ¥2/30問 | — |
| **N3: 答えが2つ以上** | **余分な正解の行だけ1条件を崩す（下記）**。連続失敗のみOpus昇格 | 小〜中 | 本文・設問・意図した正解は保持 |

### N3「答えが2つ」の直し方＝誤答を一意化（本文はそのまま）
- **原因**: これはFlash固有の“言語ミス”ではなく**設計・検算の弱さ**。2段階計算（締切逆算・合計金額・割引）で、モデルが全行×全条件を照合しきらず、**意図した正解以外の行も条件を全部満たしてしまう**。強いモデル（Opus）ほど一発率は上がるが、**100%保証はモデルではなく機械検算（一意性反証）が担う**。
- **正しい直し方＝作り直しではなく“誤答の一意化”**（プロジェクト既定 [[second-answer-drop-distractor-not-question]]）:
  1. 一意性反証は**どの行が余分な正解か**を既に返す（例: 正解=2 なのに 反証該当=[2,3] → 行3が侵入者）。
  2. その**侵入行のセルを1つだけ**変えて1条件を外す（締切を早める／料金を予算超に／曜日を変える 等）。**本文・設問・図表の他行・意図した正解は一切触らない**。
  3. 再び反証にかけ「該当ちょうど1つ」を確認。通らなければ再修正、連続失敗する問題だけ**Opusに同じ“誤答一意化”を依頼**（[[quality-critical-gen-use-opus]]）。
- **なぜOpusで直せるか**: 「行3だけ1条件崩して一意にせよ・本文不変」は**ゼロから作るより遥かに小さく検証可能なタスク**。本文・設問・正解という高価な部分を保存したまま余分な正解だけ潰せる。Flashでも反証ループで直るが、Opusは少ない回数で収束する。

## 本走行レシピ（確定・次回そのまま再利用）
**確定方針＝「Flashで生成 → 落ちたN3は誤答一意化で修理（頑固な分だけOpus）」**。スクリプト一式は本走行後に `tools\joho_gen\` へ確定版を保存（それまでは当セッション scratchpad）。パイプライン:
1. **生成** `node gen.mjs` — 級別に本文＋設問を一括生成。**題材を「帯」でローテーション**して重複を避け、**overhead込みで多め**に出す（目安 N5×1.1・N4×1.4・N3×1.6）。出力 `raw_{LV}.json`。IDは既存と衝突しない採番（例 `${level}-joho-bNNN`）。
2. **ルビ** `node ruby2.mjs` — 無ルビ漢字連を機械検出→読みのみLLM→機械挿入（無ルビ0・¥2/30問）。出力 `annotated_{LV}.json`。
3. **機械ゲート** `python gate.py annotated` — 字数/構造/ルビ0/ボーダーレス/**重複**を¥0判定。落ちたIDと理由を出す。
4. **一意性反証** `node verify.mjs` — 答えを隠し全条件照合。該当1つ＝採用、複数＝侵入行つきで要修理。
5. **誤答一意化（N3中心）** `node fix_unique.mjs` — 反証が示した侵入行のセルを1つ崩して一意化（**本文不変**）。Flashで回し、連続失敗のIDだけ `model=Opus`。→ 3・4を再実行して収束させる。
6. **理由別の最安修理**（上表）— 人名=辞書置換、字数境界=1問だけ増補、図表形ズレ=機械整形。
7. **反映** content置換 → `node --import tsx tools/content/rebuild.ts` → `npx tsc --noEmit` → `node --test` → **明示パスでcommit**（`git add -A`禁止）→ push（deploy-pagesが公開直前に目録再生成 [[ota-manifest-regen-or-stale]]）。
- **各段は独立スクリプトで実行**（サブエージェント不要・B系）。重い生成はバックグラウンド起動し、完了通知で1回だけ回収（A4）。

## コスト規律（厳守）
- **D1**: 一括 ¥1,000 超の有料生成は、**円換算の見積り＋承認を先に**。まず**各級10問のパイロット**で実費・一発合格率を実測 → その数字で本走行の費用を確定 → 承認 → 本走行。[[estimate-llm-workflow-cost]]
- **D2**: 実行後に **モデル名＋実費（円換算）** を必ず報告。
