## 0. 大原則
- **正本＝`content/problems/choukai/<daimon>_<level>.json`**（13ファイル）。`daimon∈{kadai,point,gaiyou,hatsuwa,sokuji}`／`level∈{N5,N4,N3}`（概要gaiyouはN3のみ）。

- 1ファイル = `{schema, daimon, level, languages, items[]}`。**1 item = 1 音声 = 1 設問**。
- 数量の目安：**各大問×各レベル 10問**（id連番 001〜、追加は011〜）。2026-07-23時点で**各20問・総計260問**。**2026-07-27 方針＝各大問×レベルを +20（→各40）へ**（id 021〜。全体+260問）。
- **既存問題は作り直さない**（ユーザー指示 2026-07-27）＝新方式の床ゲートは**新規追加分だけ**に効かせる。既存20問は公式より短いが据え置き。

## 1. item スキーマ（既存を template 複製するのが安全）
```
{ id:"N5-C-K-011", level:"N5", category:"choukai", type:"listening",
  subtype:"kadai", title:"課題理解",
  scenario:"交通旅行"(場面＝title直後・下記8カテゴリのいずれか。場所が無い短文＝発話/即時は"その他"可),
  qtype:"発話表現"/"即時応答"(発話/即時のみ・他は無し),
  script:"…", audio:true(概要は付けない),
  audioChoices:true(発話/即時のみ),
  i18n:{}(訳は未生成＝空),
  questions:[{ id:"…-q1", q:"設問"(発話/即時は""), choices:[…], answerIndex:0 }] }
```
- **`scenario`（場面）＝データに保存する正式フィールド**（2026-08-12 導入・全520問付与済）。8カテゴリ＝会社仕事/学校学習/店買い物/家家庭/病院健康/交通旅行/公共手続/地域近所（＋場所の無い短文は`その他`）。
  - 決め方＝`scene_ledger.classify`（**導入文の会場名を最優先**で判定・仮名会場も収録）。新規は `merge_and_gate.py` が `scenario_tag`→無効/未指定なら台本から自動確定して**保存**する。自動が誤る個別問題だけ `tools/choukai/scenario_overrides.json` に手動確定を足す。
  - 遡り付与／再集計＝`python tools/choukai/backfill_scenario.py <daimon...> --apply`。アプリ影響なし（rehydrate が素通し・テスト393緑）。
- **正解は常に choices[0]（先頭）**。課題/ポイント/概要は**実行時シャッフル**されるので先頭固定でよい。発話/即時は `audioChoices`＝音声が順に流れるため**番号固定＝正解は必ず①**（[[hatsuwa-sokuji-answer-always-1]]）。
- 選択肢数＝課題/ポイント/概要は**4**、発話/即時は**3**。
- id命名＝`<Level>-C-<K|P|G|H|S>-<3桁>`（K課題/Pポイント/G概要/H発話/S即時）。

## 2. 品質基準
### 長さ＝本文モーラ基準（2026-07-27 改訂。字数でなくモーラで合否）
- **合否は「本文モーラ数」で判定**。本文＝台本から**導入(冒頭の状況ナレ)・設問・選択肢を除いた台詞のみ**（発話/即時は短いので台本全体）。
- **基準＝公式問題の本文モーラ**。`tools/choukai/official_mora_baseline.json`（公式音声の文字起こし `問題作成の参考/文字起こし/stt_N{3,4,5}.json` を pykakasi でモーラ化・本文のみ）。各バケットに `mora_median`（中央値）・`floor_080`（×0.80）・`ceiling_120`（×1.20）。
- **新規は公式中央値の 80〜120%（floor_080〜ceiling_120）の帯内が合格**（ユーザールール 2026-07-27。±20%。帯幅は `merge_and_gate.py` の `BAND_PCT` 一箇所で変更）。`merge_and_gate.py` が機械判定し帯外を追記除外＋不足/超過モーラを表示。**短すぎ<下限＝加筆／長すぎ>上限＝短縮**。
- **直し方（2026-07-27 ユーザー指示・確定）**：**短い（<下限）→加筆**（本文に自然文を足す・答え/一意性/観点は不変）。**長い（>上限）→短縮でなく作り直し**（短縮はダミーを消す条件文を削って一意性を壊す危険があるため、縮めずに作り直す）。直したら再gate。
- **狙いは「中央値〜やや短め（帯の下寄り 80〜100%）」**（2026-07-27 ユーザー指示・「長い方が良い」は撤回）。**理由＝短縮は正解の一意性を壊す危険**（ダミーを消す条件文を削ると第2正解が復活）。だから生成は上限を超えないよう控えめに作り、**不足は安全な加筆で伸ばす＝危険な短縮を避ける**。中央値: 課題 N5 131 / N4 261 / N3 322・ポイント N5 186 / N4 219 / N3 224・概要 N3 237・発話 N5 25 / N4 25 / N3 34・即時 N5 26 / N4 24 / N3 20。帯(80-120%): 課題 N5 105-157 / N4 209-313 / N3 258-386・ポイント N5 149-223 / N4 175-263 / N3 179-269・概要 N3 190-284。※公式基準を作り直したら `official_mora_baseline.json` を再生成。
- ⚠既存20問は公式と概ね一致（課題等はやや短め）だが**修正しない＝据え置き**（ユーザー確定 2026-07-27）。帯ゲートは**新規だけ**に効かせる。
- ⚠AIは「床さえ超えれば長いほど良い」と誤りやすく**上限超過しがち**（試作で6問中5問が上限オーバー）。生成時は**中央値を明示**し、往復数を増やしすぎない。
- 話速（音声フェーズの目標・発話中拍/秒）は `md/10_聴解.md`。※**現行マスターは公式の約2〜3倍速い**＝音声フェーズで公式話速へ要再生成。

### 大問別 ダミーの技法（罠）
- **①課題理解**：次にまずすべき行動を一意特定。ダミー＝「済んだ/他人がやる/後でやる/条件で除外」で**時系列・主体**を切る。途中に条件・変更を入れて確定。
- **②ポイント理解**：設問で**観点1つ**（なぜ/いつ/いくつ/気持ち/どれ）。ダミー＝会話の他情報で観点ズレ。**本音・真の理由を最後**に置く。
- **③概要理解**（独話のみ）：全体の主張/テーマを問う。ダミー＝話に出た**部分語を流用**して要旨とズラす（細部確認にしない＝ポイント理解化を避ける）。
- **④発話表現**：矢印の人の一言。ダミー＝**視点・敬語の向き違い**（自分/相手の逆・敬語過不足・立場逆）。状況文に「誰が・何をしたいか」を明記し発話を特定。
- **⑤即時応答**：短い投げかけへの即応。ダミー＝**語かぶり＋意味ズレ/時制ズレ/立場ズレ**（無関係で即除外の弱ダミー×・逆に成立する紛らわしすぎ×）。

### 共通規律
- **答えが一意**（第2の正解なし）＝最重要（[[unique-answer-question-design]]）。第2正解が出たら**ダミーを削って直す**＝問題は捨てない（[[second-answer-drop-distractor-not-question]]）。
- 個人名なし・役割ベース・**漢数字**・話者最大2名で性別明示（`女1：`/`男1：`）。既存と場面・話題を**重複させない**。
- 割り増し作問はしない＝過不足はユーザー判断（[[no-overprovision-question-generation]]）。

### 場面の多様性（2026-07-27 追加。薄い場面から埋める）
- 既存は **店/会社/学校/家** に集中し **病院・交通旅行・公共手続・地域近所** が空（役割ベース＝[[content-borderless-no-names]]）。特に即時応答は場面が薄い。
- `python tools/choukai/scene_ledger.py` で既存の偏りを集計→`tools/choukai/scene_census.json`（各大問×レベルの `assign`＝埋めるべき薄い/空の場面リスト）。新規追加分も `--add <NEWDIR>` で加えて再集計できる。
- 新規は各体へ `assign` の薄い場面を割り当て、**既存と場面・話題を重複させない**。生成レコードに `scenario_tag`（場面カテゴリ）を必ず付与し、`merge_and_gate.py` が場面タグ重複を参考表示。

### レベル別の狙い・特徴・違い（作問の指針。詳細＝`md/10_聴解.md`総論）
- **大問構成**：N5・N4＝課題／ポイント／発話／即時の**4大問（概要なし）**。N3＝＋**概要理解**の**5大問**。
- **N5**：狙い＝**身近な場面**で「次の行動・要点・適切な一言」を**ゆっくり・はっきり**聞き取れるか。特徴＝場面が身近で**直接的**・語彙は基礎・話速最も遅い（本編≈3.45拍/秒）・課題≈ポイントで難度差が出ない。作問＝遠回しにしない／条件は1つ／基礎語彙。
- **N4**：狙い＝場面の中で「次の行動・要点・適切な一言」を**直接的**に。特徴＝場面が直接的・語彙平易・話速≈3.55拍/秒。作問＝N5より情報量・条件をやや増やすが**依然直接的**（間接表現に頼らない）。
- **N3**：狙い＝**必要な情報だけ**聞き取り、話の**要旨・意図を大づかみ**。特徴＝語彙難・展開複雑・**間接性**（本音は後半・遠回し）・概要理解が加わる・話速≈3.77拍/秒。作問＝間接的な言い回し／情報の取捨選択を要求／本音・真の理由は最後。
- **本文モーラもレベルで増える**（N3>N4>N5）＝§長さの中央値表のとおり。レベル差は「語彙・間接性・情報量・長さ」の4点で付ける（速度で難しくしない）。

### 1問チェックリスト（生成・監査で毎回・全項目○で合格）
1. **答えが一意**＝本文だけで正解が1つに決まる／第2の正解なし（ダミーはすべて本文の条件で否定できる）。
2. **正解＝choices[0]（先頭固定）**。選択肢数＝課題/ポイント/概要4・発話/即時3。選択肢の重複なし。
3. **本文モーラが帯内**（公式中央値80〜120%・**上限超え無し**＝狙いは中央値〜やや短め）。`merge_and_gate.py` で機械確認。
4. **ダミーが§2の技法どおり**（大問別の罠）。弱すぎ（即除外）・強すぎ（第2正解化）を避ける。
5. **場面が割当（薄い場面）**・既存と場面/話題が重複しない・`scenario_tag` を付与。
6. **個人名なし・役割ベース**・**漢数字**・話者最大2名で性別明示（`女1：`/`男1：`）。
7. **レベル相応**（§7の狙い・語彙・間接性）。設問は課題「まず何をするか」／ポイント「観点1つ」／概要「主旨」／発話「一言」／即時「即応」。

## 3. 新規作成フロー（実行手順）
作業用ディレクトリ（例）＝セッションの scratchpad。中間物は正本に混ぜない。
1. **参照バッチを作る**（既存を手本＋重複回避に渡す）
   `python tools/choukai/build_batches.py --scope existing --out <WORK>/batches`
2. **場面台帳を作る**（薄い場面の割当）
   `python tools/choukai/scene_ledger.py` → `tools/choukai/scene_census.json`。各大問×レベルの `assign` を生成へ渡す。
3. **大問別に5サブエージェントで生成**（1体=1大問・各レベル+20問）。Opus級・品質最優先。
   - 各体に渡すもの：`batches/batch_<daimon>.json`（手本・重複回避）＋`scene_census.json` の `assign`（割当場面）＋§2の技法・**本文モーラは中央値〜やや短め（帯 floor_080〜ceiling_120 の下寄り）**・§2のレベル別の狙い・共通規律・§2の1問チェックリスト・**自己検証（一意性/第2正解なし/本文モーラが帯内・上限超え無し/場面重複なし）**。
   - **長さの狙い方**：目標＝**中央値〜やや短め（帯の下寄り）**。**上限超過は避ける**（超過→短縮が要る→一意性を壊す恐れ）。往復を増やしすぎない。不足は後で安全に加筆できるので、控えめでよい。
   - 出力（簡易スキーマ）＝ `<WORK>/newq/new_<daimon>.json`：`{id,level,daimon,script,question(発話/即時は""),choices(正解先頭),why_unique,scenario_tag}`。
   - トークン節約：**台本本文は本体会話に載せない**。各体はファイルへ Write ＋要約のみ返す（[[subagent-hook-event-names]]の運用と同様）。
4. **自動QA→合格分だけ追記**
   `python tools/choukai/merge_and_gate.py --new <WORK>/newq`（ゲートのみ）→ 問題なければ `--apply`。
   - 合否：id衝突/形式・選択肢数(4/3)・重複選択肢＝致命／**本文モーラが帯(公式中央値80〜120%)の外＝帯外**（どちらも追記除外・不足/超過モーラを表示）。字数・場面タグ重複＝参考表示。
   - **帯外の直し方**＝短い→自然文を加筆（答え・一意性・観点は不変）／長い→**作り直し**（短縮しない＝一意性保護）。合格が目標数に届くまで＝loop-until-target。
   - 追記＝合格分のみ。既存 items[0] を template 複製し id/level/script/question/choices/answerIndex=0 を差替（スキーマ完全一致）。compact JSON で書き戻し（差分最小）。

## 4. 意味監査フロー（judge・第三者視点で確定）
1. 対象を大問別バッチ化：`build_batches.py --scope new`（新規のみ）/`--scope all`（全件）`--out <WORK>/batches_j`
2. **大問別に5判定エージェント**。§2の技法を採点ゲート化し、各問を **合格／要修正／作り直し／削除** に仕分け。出力＝`<WORK>/verdicts/verdict_<daimon>.json`（`{id,level,daimon,verdict,issues[],fix_hint,severity}`）。
3. 集計：`python tools/choukai/merge_verdicts.py --verdicts <WORK>/verdicts`
4. 修正の当て方：
   - **要修正**＝ダミー1個差替・場面/状況の一言追記・語句/レベル調整（**問題は残す**）。
   - **作り直し**＝正解が台本と矛盾/一意でない/型を成さない/レベル大幅逸脱（台本から作り直し）。
   - 修正は Python で該当 item の該当欄だけ差替（全item一括Writeは避ける＝[[large-write-64k-patch-not-rewrite]]）。

## 5. 後工程（台本確定後）

- **ビルド**：指示があった時のみ（[[build-cadence-preference]]）。build番号併記。

## 6. スクリプト・データ（`tools/choukai/`）

- `merge_and_gate.py` は追記時に `scenario` を自動保存（`scenario_tag`→無効なら台本分類）。
- `merge_and_gate.py` … 新規の自動QA（**本文モーラ帯ゲート＝公式中央値80〜120%**・帯幅は `BAND_PCT`）＋（--apply で）合格分を正本へ追記。基準＝`official_mora_baseline.json`。短い→加筆で再gate／長い→作り直し。
- `mora_check.py` … 生成レコード(list)の本文モーラを自己検証(`python tools/choukai/mora_check.py <records.json>`)。merge_and_gate と同じ body_mora/帯を使い OK/SHORT/LONG を表示。サブエージェントの自己ゲート用。
- `merge_verdicts.py` … judge の verdict 集計。
- `official_mora_baseline.json` … **公式本文モーラ基準値**（official=各バケットの mora_median/floor_080/ceiling_120・stock=既存中央値）。公式音声の文字起こし `問題作成の参考/文字起こし/stt_N{3,4,5}.json` から本文のみ pykakasi でモーラ化して算出。
- `scene_census.json` … 場面台帳（`scene_ledger.py` の出力）。
（字数・話速の実測は `md/10_聴解.md`。実測再現の使い捨てスクリプトは scratchpad で都度。）
