# 第I部 — 出題意図の全体設計（これだけ押さえれば全部読める）

## 0. 大設計思想
- **1大問 = 1つの面**しか測らない。だから同じ「語彙力」でも複数の大問に分かれる。
- 大問の集合で、能力を**面で覆う（タイル状に敷き詰める）**。
  - **文字・語彙** = 語を「**音 → 字 → 意味 → 運用**」の層で輪切り。
  - **文法** = 「**語 → 文 → 文章**」とスケールを拡大（認識→産出→統合）。
  - **読解** = 「**長さ × 読み方**」で負荷と技能を切り分け。
- **N4 → N3 の変化** = 面の構成は同じまま、**弁別を細かく**し、**読解の比重を増やす**。要求が「定型の**認識**」から「近似の**弁別**と論の**理解**」へ。

## 1. 文字・語彙（5大問）= 語を「音→字→意味→運用」で多面測定

| 大問 | 出題者の目的（軸） | 隣の大問との違い | 受験者に求めること |
|---|---|---|---|
| ①漢字読み | 漢字 → **音**を正しく取り出す | 唯一「音」だけを問う（意味は文で固定済み） | 長音・濁音・拗音・音訓の**1音単位の精度** |
| ②表記 | 音（かな） → **字**を正しく選ぶ | **①の逆向き**（読む↔書く）。字形・同音異字 | 同音で字の違う語の**書き分け** |
| ③文脈規定 | 空所に合う語を**選ぶ**（意味×共起） | ①②は語が文中に既在。③は**語そのものを選ぶ**＝意味運用へ移行 | 類義語を**文脈（共起）で1つに絞る** |
| ④言い換え類義 | 下線語 ≒ **別の語で言い換える** | ③が「文脈に合う語を入れる（産出）」なら、④は「既にある語の意味を別語で確認（同定）」＝**③の裏** | 語の意味を**保存して言い換える**深さ |
| ⑤用法 | 語を**正しく使う文**を選ぶ | ③④は意味レベル。⑤は**意味＋文法的振る舞い（自他・格・共起・対象）**の統合 | 「知っている」でなく**正しく使える** |

**分業の妙**: ①↔②は表裏（読む/書く）、③↔④も表裏（選ぶ/言い換える）、⑤が意味と文法の統合。
→ 同じ語彙力を **FORM（音・字）→ MEANING（選ぶ・言い換える）→ USE（運用）** の順に多面チェック。

## 2. 文法（3大問）= スケールを「語→文→文章」に拡大

| 大問 | 出題者の目的（軸） | 隣との違い | 受験者に求めること |
|---|---|---|---|
| ①文法形式判断 | 空所に合う**文型・機能語**を選ぶ | **部品を1つ選ぶ（認識）** | 文型知識＋文脈適合 |
| ②文の組み立て | ★の**語順**を決める | ①が「部品を選ぶ」なら②は**部品を並べて構造を作る（産出）** | バラバラの語を正しい**統語の骨組み**に |
| ③文章の文法 | 文章中の空所を**流れで選ぶ** | ①=単文、②=文、③=**文章（結束性）** とスケール拡大 | 段落の**時制・人称・論理・情報源・視点**の一貫性 |

**分業の妙**: 単文の「点（形式）」→ 1文の「線（語順）」→ 文章の「面（結束）」。→ **認識 → 産出 → 文脈統合**。

## 3. 読解 = 「長さ × 読み方」で負荷と技能を切り分け

| 大問 | 目的（軸） | 他との違い | 受験者に求めること |
|---|---|---|---|
| 内容理解（短） | 中心情報**1つ**の取り出し | メール=「次の行動」、手紙=「理由」を1問で | 要点の即時把握 |
| 内容理解（中） | 指示語・理由・**主張**の理解 | 短文の「情報取り出し」に対し**関係・解釈**へ | 「それ=何」「なぜ」「筆者はどう考える」の3層 |
| 内容理解（長）※N3のみ | まとまった論の**論理展開・概要** | 長さで負荷を最大化 | 下線部＋主張＋キーワード定義の統合 |
| 情報検索 | 条件に合う情報の**照合** | 他が「通読して理解」なら、これだけ**探して照合（非線形読み=走査）** | 日付・曜日・料金など**条件の重ね合わせ** |

**分業の妙**: 短→中→長で**読む量の負荷**を上げ、情報検索だけ**読み方そのもの**を変える（全部読ませない）。
→ 各大問固有の作問は **09_読解.md** を参照。

## 4. N4 ⇔ N3 で「受験者に求めるもの」の変化

| 面 | N4が求める | N3が求める（=一段上） |
|---|---|---|
| 文字語彙 | **定型・日常語**の認識 | 意味の**近い語の弁別**（延期/延長、欠点/不満…）。抽象語・硬い語 |
| 文法 | 日常の**基本文型** | **関係を表す機能語**（にとって／とはかぎらない／敬語／呼応副詞） |
| 読解 | 短〜中の要点把握 | **長文大問が加わり読解比重増**。社会的題材・筆者の主張 |
| 総括 | 「知っている定型を**認識**できる」 | 「**近いものを文脈で弁別**し、まとまった文章を**理解**できる」 |

## 5. 共通原則（自作でも必ず守る）
1. **1問1能力**: 1問で測る学習項目を1つに絞る（読みの問題に語彙の難しさを混ぜない）。
2. **ダミーも実在**: 誤答も級内で実在する語・形にする。荒唐無稽は当てずっぽうで消せ、測定にならない。
3. **一意性**: 正解は文脈で**1つに定まる**。「複数正解になり得る」「情報不足で選べない」は不良問題。
4. **場面は日常**: 役割名で運用し**個人名は一切使わない**——敬称付き（〜さん）・カタカナ名・姓すべて禁止、人物は役割名（留学生/学生/会社員/店員/客 等）で呼ぶ（N3は社会寄り＝仕事・地域・防災）。[[content-borderless-no-names]]
5. **難易度はレベル内で操作**: 語の頻度・文の長さ・ヒントの明示度で上下（範囲外語で難しくしない）。

### 全体の作問トーン（N3/N4教材から読み取れる共通点）
- **1問＝1つの明確な学習項目**（読み/表記/意味/文型/読解ポイントのどれか）に対応。
- 選択肢は**すべて実在する級内語・級内文型**で構成し、**文脈でのみ一意化**する（当てずっぽうで消せる明らかなダミーは置かない）。
- 語彙・場面は **N4=日常生活（学校・買い物・交通・天気・家族・仕事）中心 → N3=日常＋社会寄り**（仕事・就職面接・地域・防災・農業・少子高齢化など、社会性が上がる）。
- 公式は**固有の人名・地名**を使用するが、**当アプリは役割ベース（先生/学生/店員/客/係の人 等）に置換**する（[[content-borderless-no-names]]）。
- ルビ: **N4=文字語彙は総ルビ**、**N3=難読語のみ部分ルビ**。文法読解はどちらも級相当以上の漢字にルビ。**必ず熟語（単語）単位の`漢字（かな）`**——1字ずつに割らず、（）内はひらがなの読みだけ（漢字を入れない）。
- 正解位置はランダム（解答用紙例で①〜④が満遍なく塗られている）。

# 第IV部 — 量産の品質保証と、2026-07-17 の反省

## なぜこの節があるか

**作れば一意になる、は成り立たない。** この日は言い換え335問の再生成と用法303問の監査を行い、以下を実測で確立した。

## 確立した規律（1〜6＝中核・7〜9＝2026-07-17夜の追加）

### 1. パイロット先行。ただし**パイロットの"率"は信じるな**
各級5問で**作り方**を検証→承認→本走行。いきなり300問はレシピがズレたら丸ごと無駄。
**ただし率の推定には使えない**: パイロットで「N4=0%／N3=40%」と出たが、本走行335問では **N4=8.6%／N3=7.3%＝ほぼ同率**。
5問の偶然に「文レベルは周りの文が意味を固定するから構造的に安全」ともっともらしい理屈を後付けし、**誤った一般化を文書化した**。
→ **パイロットは"作り方"の検証にのみ使う。率を語るな。**

### 2. 独立の反証役が必須（自己検証は必要だが十分でない）
生成AIは「なぜ誤りか」の理由文を書いた**上で**第2の正解を見落とす（実証）。独立Opusだけが捕捉した。
反証役の基準は「**疑わしきはvalid**」＝甘い反証は無意味。

### 3. **追加するな、削れ**（修理より削除が強い）
言い換えで valid な誤答を差し替え（修理）たら、**新誤答が第2の正解になる事故4件（N4で19%）**→再反証の段を足す羽目に。**用法は「削除のみ・追加なし」に変更**（ユーザー提案）＝追加しなければ新バグは構造的に入らない。結果、5段（生成→反証→修理→再反証→確定）が**2段（反証→削除）**・体数20→11に減り**同時に安全**に。→ **既存の誤答があるなら作り直すより削る。**

### 4. 誤答は6→5→4→3で減らしてよい
4択に必要な誤答は3個。**第2の正解を作るくらいなら減らす**。
同義語が密集する語（活気＝活力/元気/勢い/にぎわい）は6個作れないのが正常。
**下限3を割ったら自動修正せず、元データを温存して人に報告する**（中途半端に壊した問題を残さない）。

### 5. **監査は1回では足りない。和集合を取れ**（この日の最大の発見）
偶然の二重実行が再現性テストになった。**同じ問題を2回判定させると結果が食い違う**:

| | 実測 |
|---|---|
| 2run で削除対象が完全一致 | **59%**（180/303問） |
| 両方が指摘 | 421件 |
| **1回目のみ指摘**（2回目が見逃し） | **94件** |
| **2回目のみ指摘**（1回目が見逃し） | **75件** |
| 和集合 | **590件** |

→ **1回だけなら約12%の本物のバグを取りこぼす**（clearですら10%食い違う）。**損害は非対称**＝良い誤答の誤消し＝軽微（下限3で保護）／第2の正解の見逃し＝**重大（バグ出荷）**。→ **多数決でなく和集合**（1回でもvalidなら削除）。**2runでも未収束**（2回目だけが75件を新発見）＝3run目も数十件見つけるはず。「取りこぼしゼロ」とは言えない。

### 6. ゲート（未検証は出題しない）は**廃止した**
一時は `verified` のみ出題にしたが、**一般ユーザーは存在せず開発者しか触らない**ため、
未修正の問題を隠すより見えている方がよい（ユーザー判断 2026-07-17）。`verified` は**進捗メタ**として残す。
※もし将来リリース後に再導入するなら、**ゲートはデータと同じコミットで入れる**こと（単独投入でその大問が全級から消滅する）。
※**再導入を「バグ修正」と思って提案するな**（2026-07-17夜に実際にやりかけた）。廃止は判断であって欠落ではない。

### 7. **一意性は「正解 vs 誤答」だけでは足りない。誤答どうしも見ろ**（2026-07-17夜の発見）

規律1〜6は「誤答が正解になっていないか」の話。**それだけでは穴が残る**: 答えは1つだから、**等価な誤答が2つあれば語の意味を知らなくても論理で両方消せる**（「AとBは同義→答えは1つ→両方誤答」＝日本語力でなく論理で解ける）。

| 型 | 実例（すべて実際に検出） |
|---|---|
| **同義** | 朝→午前 の誤答に「昼」と「午後」／いかが→どう に「どこ」と「どちら」／「晩」と「夜」／「ちょっと」と「少し」 |
| **含意（上位下位）** | 東京 と 日本／大学生 と 学生／紅茶 と お茶／反対 と 違う ＝「Aが正解ならBも正解」で2つまとめて消える |
| **同一事態の別記述** | 「先生が学生に貸した」と「学生が先生に借りた」＝**同じ出来事**（→ 04_言い換え類義.md ④-N5 の `perspective_cross`） |

→ **一意性テストは「各誤答 vs 正解」の縦だけでなく、「誤答どうし」の総当たりを必ず回す。**
→ 反証役にも `pairIssue`（同義/含意な誤答の添字ペア）として報告させる。
→ この基準で作問不能になる語がある（例「同じ→一緒」＝独立した誤答が実質1個で下限3に届かず **needsDrop**）。**それが正しい。**

### 8. **表層で正解が浮いてはいけない**（2026-07-17夜の発見）

意味が分からなくても、**形が違うものを選べば当たる**問題を作ってしまう。

| 型 | 実例 |
|---|---|
| **助詞** | 「売る」の視点転換で**正解だけ「から」**、誤答は「に」 |
| **語形（活用型）** | `negation_cross` で「暇」を作ると正解「忙しくないです」（**い**形容詞）に対し誤答「元気じゃないです」（**な**形容詞）＝否定形が割れる |
| **構造** | 正解だけ述語ごと変わる（御飯→食事 で「食事を**食べ**ましたか」＝コロケーション違反を避けた結果） |

→ 正解と誤答は**同じ助詞・同じ文型・同じ活用型**で揃える。
→ 格が変わる語対（分かる→知る＝ガ格→ヲ格）は、**正解と誤答を全て同じ形に揃え、浮きを stem 側に寄せる**。

#### ★engineの3個抽出＝浮きは「確率」で漏れる（この計算が判定の核）

engineは誤答5個から**ランダムに3個**抽出して4択にする。だから**同属性の誤答が何個あるか**で浮く確率が決まる。

| 正解と同属性の誤答（5個中） | 抽出3個から全部抜ける確率 | 結果 |
|---:|---:|---|
| 0個 | **100%** | 毎回浮く |
| 1個 | **40%**（C(4,3)/C(5,3)＝4/10） | 10回中4回浮く |
| 2個 | **10%** | 10回中1回浮く |
| 3個以上 | **0%** | 浮かない |

#### ★★ 誤答を【4個】にすると 0% になる（2026-07-17・修理役の発見）

「5個中3個以上に揃えろ」は**万能ではない**。属性を3:2にすると、**今度は少数側(2個)が全部抜ける回(1/10)に、
正解が「少数側でない方」として浮く**（＝浮きが裏返るだけ）。

**誤答4個・属性2:2 なら、3個抽出で必ず1個しか抜けないので【両方の属性が必ず残る】＝0%。**

```
誤答5個・属性3:2 → 少数側2個が両方抜ける回が 1/10  … 浮く
誤答4個・属性2:2 → 1個しか抜けない＝必ず両方残る   … 0%
```

実例: 「零→ゼロ度」でカタカナ3個にすると、マイナス系2個が抜けた回に正解だけ「マイナスの付かない語」として浮いた。
誤答4個（カタカナ2＋漢数字2）にして解消。

→ **属性が2種類しか作れない語では、誤答を5個でなく4個にする方が強い。**
　 規律4「誤答は6→5→4→3で減らしてよい」と規律3「追加するな、削れ」がここでも効く。**減らすと強くなる場合がある。**

### 9. **生成役に「レシピの不備を指摘しろ」と言え**（費用対効果が最も高い）
2026-07-17夜、生成役8体が**レシピの不備を8点**指摘。うち3点は**設計の根本誤り**で、無ければ160問全部が同じ欠陥で出荷されていた（`perspective_cross`の2×2崩壊・`adv`型の欠落・「範囲外禁止」と「rebuildは原文どおり」の衝突）。**実装役は仕様の最初の読者＝最良のレビュアー。** 指摘欄のコストはゼロに近い。

13. **★誤答どうしを総当たりしたか**：同義・**含意（上位下位）**・同一事態の別記述になっていないか。
　　等価な2択は語を知らなくても両方消せる（→ 第IV部 規律7）

　　（engineの3個抽出で約1/10の回に浮く）（→ 第IV部 規律8）
15. **★生成役にレシピの不備を指摘させたか**：実装役は仕様の最初の読者。指摘欄のコストはゼロに近い（→ 第IV部 規律9）

# N5 総論（全大問に共通するN5の設計原理と技術制約）

> 出典: 問題対策 第VI部（`問題作成の参考/N5_漢字語彙.pdf` 8頁・全35問を実読）。**大問別のN5作り方は 01〜04 の各ファイル末尾**にある。ここには大問を貫く原理と技術制約だけを置く。

## 0. N5の核心発見 —「2×2クロス」が全大問を貫く

**N5の出題者は、二値の軸を2本だけ選び、それを交差させて4択をちょうど作っている。**

軸A＝{正しい, 誤り}、軸B＝{正しい, 誤り} を掛けると、セルは 2×2＝**ちょうど4個**。そのうち**両方正しい1個だけが正解**で、残り3個が自動的に誤答になる。

```
          軸B:「校」  軸B:「枚」
軸A:「学」   学校 ←正解   学枚
軸A:「宇」   宇校        宇枚
```

この設計が強い理由は4つある。

1. **一意性が構造的に保証される** — 両軸を満たすセルは定義上1個しかない。「第2の正解」が原理的に生まれない（第IV部の最大の苦労が、設計だけで消える）。
2. **3つの誤答が全て等しくもっともらしい** — 「明らかに変な選択肢」がゼロになり、当てずっぽうで消せない。
3. **1問で2つの知識を同時に測れる** — どのセルを選んだかで「どちらの軸を間違えたか」が特定できる（＝**誤答が診断情報になる**）。
4. **作問が機械的になる** — 軸を2本決めれば残りは自動生成。量産と相性が極めて良い。

### ★成立条件 — **2軸が意味的に独立であること**（2026-07-17夜に実走行で判明）

上の4つの利点は**無条件ではない**。**4セルが4つの「別物」になる時だけ**成り立つ。
2軸が意味的に絡んでいると**セルが融合し、利点1（一意性の保証）が逆に崩壊する。**

| 例 | 軸 | 4セル | 独立か |
|---|---|---|---|
| 学校（②表記） | {学,宇} × {校,枚} | 学校・宇校・学枚・宇枚 | ✓ **4つの別の文字列** |
| 暗い（④否定） | {あかるい,しずか} × {肯定,否定} | あかるい・あかるくない・しずか・しずかでない | ✓ 4つの別の意味。**stemは交差の外** |
| 貸す（④視点） | {主語の向き} × {貸す,借りる} | **2つの出来事にしかならない** | ✗ **絡んでいる** |

```
貸す の 2×2 ＝ 4セルに見えるが…
  先生が学生に貸した ┐ 本が 先生→学生 に動く … stem
  学生が先生に借りた ┘ ＝【同一の出来事】     … 正解（だから正解になる）
  先生が学生に借りた ┐ 本が 学生→先生 に動く
  学生が先生に貸した ┘ ＝【同一の出来事】     … 互いに同義＝両方は誤答に置けない
```

**「向きを逆にする」と「動詞を裏返す」が同じ操作**なので、両方やると元に戻る。だから軸が独立でない。

→ **軸を立てたら必ず「4セルが4つの別物か」を数えろ。** 数えずに「クロスだから安全」と書くと、
　 3セル目に**stem 自身**が入る（＝100%の第2の正解）か、**2セルが互いに同義**になる（＝2つまとめて消せる）。
　 **形（字・音）の軸は独立しやすく、意味・視点の軸は絡みやすい。** 前者＝①②、後者＝④の視点転換。

## 5. アプリ実装で必ず踏まえること（N5作問の技術制約）

### 【最重要】2×2クロスは「誤答プールちょうど3個」でしか成立しない

`app/src/data/daimon.ts` の `build4Choices` は、**誤答プールが4個以上あると、出題ごとにランダムに3個だけ抜き出す**（毎回同じ誤答だと暗記されるため）。

```ts
const picked = distractors.length > 3 ? sample(distractors, 3, rng) : distractors;
```

つまり **プールに4個以上入れた瞬間、2×2クロスの4セルのうち1個が毎回ランダムに欠ける＝クロスが壊れる。**

| 大問 | 現行の誤答プール | クロス可否 |
|---|---|---|
| ①漢字読み | **3個固定** | ✓ そのまま作れる |
| ②表記 | **3個固定** | ✓ そのまま作れる |
| ③文脈規定 | 3〜5個 | △ **クロスにするなら3個に固定**（ただし③は元々クロス型ではないので問題なし） |
| ④言い換え | 3〜6個 | △ 同上（クロス型の問題だけ3個に固定） |
| ⑤用法 | 3〜6個 | — N5に用法は無い（公式・アプリとも）✓ |

**結論**: ①②は制約なくクロス化できる。④で「反対語の否定」「授受の視点」のクロス型を作る場合は、**その問題の誤答を必ず3個ちょうどにする**。
