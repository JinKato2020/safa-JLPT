## 2. 大問別の音声構造（＋堅牢化）

台本は `content/problems/choukai/*.json` の各 item の `script` と `questions[].q / choices` から作る。
**基本方針＝「話者・番号と台詞を1セットで確定し、境界は推測せず検証で確定」。**

### 対話（課題理解 kadai / ポイント理解 point）
```
script 先頭段落 = 導入(場面＋質問)  → Aoede
（空行）
女1（役割）: … / 男1（役割）: …    → 話者keyごとに Orus/Leda（2人目 Fenrir/Kore）
questions[0].q = 設問（末尾でもう一度）→ Aoede
```
- 連結順: 導入 →(1.4s)→ 対話本文 →(1.6s)→ 設問。ターン間 0.3s。選択肢は問題用紙（音声化しない）。
- **声のぶれ対策＝話者ごとに全発話を1コール生成→無音分割**（ピッチ安定＋抑揚）。**話者keyで台詞をバインド**して対話順に並べ戻す＝**入れ替わり構造的に不可**。
- **分割の妥当性を「尺の比率」で検証**（STT不要）: 各セグメントの尺が**文字数比から期待される尺**の 0.55〜1.8 倍に収まるか。外れたら（＝境界ミス/併合）**台詞ごと個別生成にフォールバック**（順序・声は確定なので必ず正しい）。
- 最後に全体を文字起こし→台本と **LCS≥0.80**（脱落・誤読の最終ネット）。

> 旧方式の失敗（2026-07-24）: 「一番長い無音N-1個で分割」だけに頼ると、台詞内の文間無音を境界と誤認→**併合/ズレ→客と店員が入れ替わる**。しかも全体LCSは語順しか見ないので**声の入れ替わりを検出できず素通り**。→ 上記の「尺比率検証＋話者keyバインド」で解決。

### 独話（概要理解 gaiyou＝N3のみ）＝ 独話 ＋ 選択肢
```
script 先頭段落 = 場面のみ（質問は言わない）→ Aoede
（空行）
女1：…（1話者のモノローグ）           → Leda（男なら Orus）
questions[0].q = 設問                    → Aoede
（選択肢を読み上げ）
```
- 連結: 導入 →(1.4s)→ 本文 →(1.6s)→ 設問 →**(1.0s)→(番号→(0.3s)→選択肢→(0.6s))×4**。
- **番号＝独話と同じ声の既存合格クリップ（原速）／選択肢＝独話と同じ声（best-of-2）**＝1問を通して同一音声で安定。
- 本文は1コール生成＝クロスコールのぶれ無し。LCS検証あり。

### 発話表現 hatsuwa / 即時応答 sokuji（audioChoices）
```
script = 本文（状況＋「何と言いますか」等） / questions[0].choices = 読み上げる3択
```
- 1問1声。**声＝既定 Leda（女）／台本が男性役のときだけ Orus（男）**（男性役＝父/息子/男教師等 男性全般＝`hs_voice()` の MALE_RE/FEMALE_RE。2026-07-25。旧「奇数Orus/偶数Leda」は廃止）。
- 連結: 本文 →(1.0s)→ [番号→(0.4s)→選択肢] ×n（選択肢→次番号は0.8s）。
- **選択肢は Excel のセル方式に忠実に「各選択肢＝個別コール生成」**＝番号↔選択肢のズレ構造的に不可。番号だけ Chirp3 合格クリップ。
- **棒読み（元気ない）テイク対策＝best-of-2**: 各選択肢を2回生成し、**抑揚（F0のばらつき）が大きい方**を採用。

## 3. 音の処理チェーン（確定パラメータ）

| 項目 | 値 |
|---|---|
| サンプルレート | 24kHz mono / 16bit PCM |
| 速度 | **全レベル 1.0倍（一定・レベル非依存）**（番号も原速）※减速は廃止（2026-07-24 ユーザー決定） |
| 間 | 導入→本文 **1.4s** / 本文→設問 **1.6s** / 対話ターン **0.3s** |
| 発話/即時の間 | 本文→番号 **1.0s** / 番号→選択肢 **0.4s** / 選択肢→次番号 **0.8s** |
| 概要選択肢の間 | 設問→番号 **1.0s** / 番号→選択肢 **0.3s** / 選択肢→次番号 **0.6s** |
| 音量 | 全パーツ **-20dBFS** RMS 正規化（ピーク -1dBFS） |
| トリム | 各パーツ前後の無音を除去（前0.02s/後0.03s余白） |
| 出力 | mp3 128k |

### やってはいけない（学びの罠）
- **境界を「無音の長さ」だけで推測しない**。台詞内の文間無音を誤認して入れ替わる。→ 尺比率検証＋話者keyバインド＋個別生成フォールバック。
- **全体LCSは声の入れ替わり・番号ズレを検出できない**（語順しか見ない）。→ 構造で防ぐ（バインド／セル別生成）。
- **ピッチ補正（rubberband）は使わない**。formant がずれて「かすれ・不自然」。RAW ＋ best-of-N が最も自然。
- **わかち書きの空白は TTS 前に除去**（`clean`）。空白があると微小ポーズが入り PTR が狂う。
- **「あと」前の変な間**は Chirp3 特有の読み間違い。**Gemini に変えて解消**（`N3-C-G-001` 実測: 「あと」推定1.70s に無音無し）。
- **棒読みテイク**は生成のばらつき。best-of-2（抑揚F0ばらつきで採点）で回避。
- **Charon は滑舌が甘い＋减速で悪化**。→ 男声は Orus に変更（audition 判断）。

# 公式リファレンス音声（目標の音・2026-07-25 追加）
- 場所: `問題作成の参考\{N3,N4,N5}\*.mp3`（公式JLPT聴解サンプル音声。N3=38本 / N4=36本 / N5=31本・track番号順）。対応する問題用紙=同フォルダの `N?_聴解.pdf`（印刷面のみ＝台本・設問・正解は非掲載）。

- 実測（サンプル7本）: mean_volume 平均 ≈ -18.9dB（-17〜-21dB）、peak ≈ -0.3〜-2.4dB。→ 現行 -20dBFS/peak-1dBFS はほぼ一致（必要なら -19dB に寄せる）。

# 既知の落とし穴：Flashが「テキスト生成モード」で400（2026-07-25 確定）

- 症状: 一部の問題だけ `HTTP Error 400 / "Model tried to generate text, but it should only be used for TTS."`。長い品質プロンプト＋末尾が疑問文（例「二人は まず 何を しますか。」）のとき、Flashが読み上げでなく“回答”しようとしてテキストを生成→AUDIO専用リクエストで弾かれる。**確率的**（同じ台本でも再試行で直ることがある）。
- 真因の罠: 生成器 `gen_choukai_json.py` はコスト集計のため `M.flash_pcm` を自前の `flash_pcm_acc` に**差し替えている**。よって `build_choukai3.flash_pcm` 側だけ直しても素通り。**TTS送信のガードは `flash_pcm_acc` に入れる**こと。
- 対策（実装済）: text生成400を踏むと以降 `M.SAFE_READ`（「返答せず読み上げるだけ」の最優先ガード）を前置してループ内で再試行→尽きれば `RuntimeError` に変換し、`one()` の Chirp3 フォールバックで必ず音声化。**429/500/503 は従来どおり**（クレジット枯渇の暴走リトライにはしない）。同ガードは `build_choukai3.flash_pcm`（標準経路）にも二重で設置。
- 400本文の捕まえ方（診断）: `flash_pcm` を `except HTTPError as e: e.read()` でラップして本文を読むと理由が判る（生成器は本文を握り潰すため素の失敗理由が出ない）。
