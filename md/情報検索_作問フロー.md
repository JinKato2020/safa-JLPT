## 4. 機械的エラー処理（①生成に必須）

- **個人名禁止**：公式は「留学生のソンさん」等と名前を使うが当アプリは**役割のみ**（留学生/学生/会社員）＝[[content-borderless-no-names]]。実在地名・機関名・人名は gate.py の BANNED＋監査で落とす。
- **総ルビ・熟語単位**：`漢字（かな）`。1字ずつ（市（し）民（みん））でなく熟語（市民（しみん））。**（）内に漢字を入れない**。ルビは自レベル同等以上の漢字に付与（[[content-borderless-no-names]] とは別のルビ規律＝レベル別 rubyGate）。
- **一意性の担保**：全条件を満たす行が**ちょうど1つ**。境界を明示（T7）。

## 7. 運用実録・落とし穴・学び（次回追加作問の必読）

**A. モデルの落とし穴【最重要】**：`gemini-3-flash-preview` は本走行日、単発1リクエストすら 90s×2 で AbortError（内部 thinking か過負荷）。**必ず `gemini-2.5-flash` ＋ `thinkingConfig.thinkingBudget=0`**（診断で915ms正常）。走行前に `gdiag.mjs` で疎通を1回確認してから本走行に入る。生成が以前 preview で通ったのは「別時刻にたまたま通った」だけ＝再現性なし。

**B. fetch 堅牢化【必須】**：全 Gemini 呼び出しに **90秒 AbortController ＋ 3回リトライ ＋ `connection: close`**。無いと N3 のどれか1バッチで無応答→**27分ハング**（node CPU が1秒しか使われていないことで判明）。verify.mjs はこれで解消。

**C. ②「一意性チェック」と「誤答修正」を分ける理由**：②検算は **answerIndex を隠して「全条件を満たす選択肢を全部列挙」** する純検算。正解を見せると追認バイアスで常に「1つ」と答えてしまうので、入力から正解を外すのが肝。修正は別タスク（どの誤答にどの条件を1つ足して外すか）で、検算と混ぜると出力が濁る。→ blind 検算（verify.mjs）で「該当が1個でない」問題だけ抽出→fix 段（fix_unique.mjs／Opus）で誤答に条件追加。列挙0個＝正解自体が条件を満たさない→正解側を修正。

**D. ID 取り違えバグ**：検算 AI が **設問 id（末尾 `-q` 付き）** を返し、本体 id と突合して全外れ→「全部要修理」化。照合で `-q` を吸収する **norm 処理** を必ず入れる。これを踏んで1回目の ¥71 が無駄になった。

**E. Opus の 64k 出力制限**：full-item をそのまま返させると 64,000 出力トークン超で失敗。**出力は「figure ＋ ja.explain のパッチだけ」＋1バッチ 5〜6問に分割**。`merge_opus.py` が元 item にパッチを接ぎ木（body/choices/answerIndex/ルビ/他言語 i18n は元のまま温存）＋処理済 id を raw から除去。

**F. 字数の許容と補修**：目標字数（N5 250／N4 400／N3 600）に対し **−50 以内は採用**。−50 超だけ **中立テキスト補修**（intro/footer/notes に答えへ影響しない文を足す＝`add_notes.py` 型）。**削除ではない**。字数は「ルビ `（かな）` を除いた全表示テキスト＋設問＋選択肢」で数える（strip 後に空白除去）。

**G. 実在名の補修**：削除でなく **役割・中立語へ置換**（田中→受付担当／京都→古都／新宿→中央／田中佐藤鈴木高橋→Ａ〜Ｄ 等）。ボーダーレス＝[[content-borderless-no-names]]。選択肢側でも名前を使っていたら統一置換（自動骨格照合が偽陽性になるので手動で骨格一致を確認）。

**H. 最終段は削除（backfill しない）**：④でも一意にならない問題は削除。過不足はユーザー判断＝[[no-overprovision-question-generation]]。今回5問削除。

**I. ③④Opus は ¥0**：旧「Opus 段 ≈¥5,700」は **撤回**（fix_unique が Opus を有料 API $15/$75 で呼ぶ設計時の見積り）。ユーザー確定フローでは ③④Opus＝本セッション（Claude 枠 ¥0）。**有料は②Gemini のみ**。トークンは大きいので workflow で少数の大きめサブエージェントに束ねる（B2/B4）＋パッチ出力で軽量化。

**J. ルビ再チェック**：`ruby2.mjs` はレベル非依存＝無ルビ漢字連を全部ルビ化・冪等（既ルビ `漢字（かな）` は再マッチしない）。**Opus が figure 値を変えた後は「無ルビ0」を再チェック**（新出漢字が混ざる）。データ標準は実務上「無ルビ0（全部ルビ）」。

**K. アプリ反映の検証（幽霊ファイル回避）**：`content/problems/dokkai/joho_{LV}.json` が正本→`rebuild.ts` が `_manifest.json`（count/sha256）と `bundled.generated.ts` を再生成。**`bundled.generated.ts` はファイル一覧が不変なら差分ゼロ＝正常**（静的 import で中身は同梱される）。反映確認は「import に `joho_N*` があるか」＋「manifest の count が一致するか」を実データで見る＝[[verify-app-reads-the-file-you-edit]]。

**L. テストと翻訳の順序**：`passageTransNe.test.ts` は全読解にネパール訳を要求するが、**情報検索は InfoSearchFigure 描画でネパール訳の導線が無い**→テストから joho subtype を除外するのが正しい。**翻訳（ネパール語含む10言語）は日本語確定後に最後にまとめて実施**（ユーザー確定＝先に翻訳すると日本語修正で全やり直し）。現状の赤（`passage_grammar` 0/200）は既存欠落で無視でよい。**CI（build-jlpt.yml）は `npm test` を実行しない**＝テスト赤はビルドを止めない。

**M. QA 偽陽性**：「みなさん」＝呼びかけで個人名でない／補足の括弧 ≠ ルビ＝[[qa-name-ruby-false-positives]]。

**N. トークン規律**：検算は **毎バッチ即ディスク保存＋再開版**（`verify_{LV}.raw.json`）で会話に生データを載せない。本体は run ID ＋完了フラグだけ持つ（A1/A2）。gate.py のログは `PYTHONIOENCODING=utf-8` を付けないと cp932 で化ける。
